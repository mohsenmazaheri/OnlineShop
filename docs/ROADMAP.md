# نقشهٔ راه و فازبندی پروژهٔ OnlineShop

> هدف: فروشگاه اینترنتی **تک‌فروشگاهی برای کسب‌وکارهای کوچک** (تعداد مشتری کم تا متوسط)، سریع، زیبا، امن،
> چندزبانه، **PWA و موبایل‌محور**، با انبارداری و حسابداری، **Cross-Platform** (لینوکس و ویندوز).
>
> هر فاز یک خروجی قابل اجرا و قابل تست دارد. فاز بعدی فقط وقتی شروع می‌شود که «معیار پایان» فاز قبل برآورده شده باشد.
> وضعیت‌ها: ✅ انجام شد · 🔄 در حال انجام · ⬜ شروع نشده

## تصمیم‌های معماری (ثبت‌شده)

| موضوع | تصمیم |
|---|---|
| ساختار مخزن | **Monorepo**: بک‌اند ‎.NET و فرانت‌اند Next.js در یک مخزن. |
| فرانت‌اند | **Next.js (React + TypeScript)** برای ویترین فروشگاه و پنل مدیریت؛ SSR/ISR برای سرعت و SEO؛ **PWA** (نصب‌پذیر، Service Worker، کش آفلاین پوسته)؛ طراحی Mobile-first. |
| بک‌اند | **ASP.NET Core 10 Web API** (پروژهٔ MVC فعلی به API تبدیل می‌شود؛ Viewهای Razor در فاز ۱ حذف می‌شوند). |
| احراز هویت بین Next.js و API | الگوی BFF: کوکی `HttpOnly`/`Secure`/`SameSite`، بدون نگهداری توکن در `localStorage`. |
| پایگاه داده | **Code-first با Migration جداگانه برای هر پایگاه داده.** هدف اول **PostgreSQL** (✅ نصب‌شده روی سیستم توسعه)، سپس SQL Server و MySQL. نام جدول/ستون‌ها `snake_case`. |
| انتخاب پایگاه داده | تنظیم `Database:Provider` (`PostgreSql` / `SqlServer` / `MySql`) + یک اسمبلی Migration برای هر Provider. |
| Cross-Platform | فقط APIهای چندسکویی؛ Docker Compose (postgres + api + web)؛ راهنمای اجرا روی لینوکس (systemd + Nginx) و ویندوز (IIS / Windows Service). |
| نقش‌ها | دو حالت: **فروشگاه یک‌نفره** (مالک فقط نقش `Admin` دارد و همه‌چیز را می‌بیند) و **فروشگاه با تقسیم وظایف** (`Manager`، `Warehouse`، `Accountant`). مجوزها Permission-based (Policy) هستند و نقش‌ها مجموعه‌ای از مجوزها. نقش Seller (چندفروشنده) حذف شد. |
| ارز و درگاه | قابل تنظیم توسط **مدیر سیستم** برای هر استقرار (پایین‌تر). |
| پیامک | **اختیاری.** پیش‌فرض خاموش؛ همهٔ امکانات بدون پیامک کار می‌کنند. با روشن کردن، OTP و اطلاع‌رسانی پیامکی فعال می‌شود. در نسخهٔ ایران عملاً روشن است (پایین‌تر). |
| مدل استقرار | **نصب جدا برای هر فروشگاه** (Single-tenant): هر فروشگاه یک کانتینر و یک دیتابیس جدا. بدون `tenant_id` در مدل داده. همهٔ فروشگاه‌ها از یک Docker image نسخه‌دار به‌روز می‌شوند. |
| کانال فروش | فقط **فروش آنلاین کالای فیزیکی به مشتری نهایی (B2C)**. بدون POS، بدون محصول دیجیتال، بدون فروش عمده. |
| قیمت چندارزی | **ارز پایه + نرخ تبدیل:** قیمت فقط در ارز پایه وارد می‌شود؛ بقیهٔ ارزها با نرخ تبدیلِ مدیر و قاعدهٔ گرد کردن هر ارز محاسبه می‌شوند؛ قیمت دستی برای محصولات خاص مجاز است. مبلغ سفارش در ارزی که مشتری پرداخت کرده ثبت و قفل می‌شود. |
| مالیات | **فقط نرخ ساده:** یک نرخ مالیات برای هر فروشگاه + انتخاب «قیمت‌ها با مالیات/بدون مالیات» + فاکتور PDF با شمارهٔ پیوسته. انطباق قانونی (سامانهٔ مودیان، VAT اتحادیهٔ اروپا، e-HDM) با خود فروشنده و حسابدارش است و در راهنما ذکر می‌شود. |
| بازار نسخهٔ ۱ | **همهٔ بازارها هم‌زمان** (ایران، ارمنستان، اروپا) با همهٔ زبان‌ها و درگاه‌ها. |
| برند فروشگاه | **چند قالب آماده:** نام، لوگو، رنگ اصلی، فونت و بنرها از پنل + چند قالب چیدمان برای صفحهٔ اصلی و لیست محصولات. |
| ترجمهٔ محتوا | **فقط دستی:** بدون سرویس خارجی؛ هر فروشگاه فقط زبان‌هایی را فعال می‌کند که ترجمه کرده؛ محتوای ترجمه‌نشده به زبان پیش‌فرض برمی‌گردد (و در آن زبان `noindex` است). |
| موتور جستجو | پشت `IProductSearch`، با تنظیم `Search:Provider`: **PostgreSQL پیش‌فرض** (Full-Text + `pg_trgm`)، **OpenSearch** یا **Elasticsearch** اختیاری روی سرور خود فروشگاه. PostgreSQL همیشه منبع حقیقت است؛ ایندکس با Outbox همگام می‌شود و اگر موتور از دسترس خارج شود، جستجو به PostgreSQL برمی‌گردد (فاز ۶). |
| SEO و بازاریابی | طراحی کامل در **[SEO-MARKETING.md](SEO-MARKETING.md)**: SSR/ISR، آدرس `/{locale}/p/{number}/{slug}`، hreflang، Schema.org، Sitemap، Redirect، بلاگ، فیدهای Google/Meta/ترب/ایمالز، ابزارهای سنجش فقط با رضایت کاربر. |

### ارز و درگاه پرداخت (تنظیمات مدیر سیستم)

- مدیر سیستم ارزهای فعال، ارز پایه، نرخ تبدیل (دستی) و درگاه‌های فعال را انتخاب می‌کند؛ هر درگاه فقط ارزهای پشتیبانی‌شدهٔ خود را می‌پذیرد.
- پیش‌تنظیم‌های پیشنهادی (قابل تغییر):

| منطقه | ارزها | درگاه‌ها | ورود |
|---|---|---|---|
| اروپا | EUR، USD | Stripe، PayPal | ایمیل، Google، Facebook، Microsoft |
| ارمنستان | AMD، EUR، USD | Stripe، PayPal | ایمیل، Google، Facebook، Microsoft |
| ایران | فقط IRR | زرین‌پال، سداد، به‌پرداخت ملت | **پیامک (OTP)** + ایمیل؛ ورود خارجی خاموش |

- مبلغ همیشه همراه کد ارز ذخیره می‌شود (Value object `Money`)؛ تعداد رقم اعشار از ارز می‌آید (ریال و درام بدون اعشار).
- **Paddle از فهرست درگاه‌ها خارج شد:** فقط محصولات دیجیتال را می‌پذیرد و برنامه فقط کالای فیزیکی می‌فروشد. اگر روزی محصول دیجیتال اضافه شود، دوباره بررسی می‌شود.

### نسخهٔ ایران

- میزبانی روی **سرور داخل ایران** (درگاه‌های شاپرکی معمولاً IP ایران می‌خواهند).
- ورود اصلی با **کد پیامکی** + ایمیل؛ Google/Facebook/Microsoft خاموش.
- **هیچ وابستگی خارجی در زمان اجرا:** فونت‌ها، آیکون‌ها، اسکریپت‌ها و تصاویر روی سرور خود فروشگاه (این قاعده برای همهٔ نسخه‌ها اجرا می‌شود؛ برای GDPR در آلمان هم لازم است).
- Docker Hub و برخی مخازن بسته (NuGet/npm) از ایران محدودند: imageها خارج از ایران در CI ساخته و در یک رجیستری در دسترس از ایران منتشر می‌شوند.
- تاریخ شمسی، ارقام فارسی و یکسان‌سازی «ی/ي» و «ک/ك».

## فاز ۱ — Monorepo، معماری و زیرساخت 🔄

**خروجی:** اسکلت کامل قابل اجرا روی لینوکس و ویندوز.

```
apps/web/                                   Next.js 16 (TypeScript, App Router, Cache Components, PWA)
src/OnlineShop.Domain/                  موجودیت‌ها (بدون وابستگی)
src/OnlineShop.Application/             Use caseها، Result<T>، IApplicationDbContext، StoreOptions
src/OnlineShop.Infrastructure/          EF Core/PostgreSQL، Identity، Data Protection، Seeder
src/OnlineShop.Infrastructure.Migrations.PostgreSql/
src/OnlineShop.Api/                     ASP.NET Core Web API
tests/OnlineShop.UnitTests, tests/OnlineShop.IntegrationTests (PostgreSQL واقعی)
deploy/                                     Dockerfileها، docker-compose، نمونهٔ nginx
```

انجام شد ✅
- Node.js 26 LTS روی سیستم توسعه؛ تفکیک لایه‌ها؛ Central Package Management؛ Analyzerها با «هشدار = خطا».
- API: endpointهای `/api/v1/store` و `/api/v1/catalog/categories`، OpenAPI (تولید در زمان build + کلاینت تایپ‌شدهٔ TypeScript)، `ProblemDetails` با کد خطا، `Result<T>`، Serilog، `/health/live` و `/health/ready`، Options validation در Startup.
- امنیت API: هدرهای امنیتی، HSTS، Rate limiting، تنظیم امن Forwarded headers، کلیدهای Data Protection در پایگاه داده، OpenAPI فقط در Development.
- Next.js: مسیرهای `/{locale}` با RTL/LTR، canonical/hreflang، robots/sitemap/manifest، آیکون PWA، Service Worker (صفحات همیشه از شبکه)، صفحهٔ آفلاین، CSP و هدرهای امنیتی، endpoint بازسازی کش با رمز مشترک.
- **یک image برای همهٔ فروشگاه‌ها:** تنظیمات فروشگاه فقط در API است و Next.js آن‌ها را در زمان درخواست می‌خواند؛ build به API نیاز ندارد (با یک build، دو پیکربندی متفاوت آزموده شد).
- Docker (API، web، PostgreSQL)، `.env.example`، نمونهٔ nginx، workflow CI (build، تست با PostgreSQL، اسکن آسیب‌پذیری، بررسی هم‌خوانی Migration و OpenAPI، ساخت image).
- تست‌ها: ۶۹ واحد + ۱۰ یکپارچه‌سازی (.NET) و ۵۴ تست Next.js.

باقی‌مانده ⬜
- اجرای واقعی `docker compose up` روی لینوکس و ویندوز (Docker روی سیستم توسعه نصب نیست) و اولین اجرای سبز CI در GitHub.
- ثبت Service Worker در یک مرورگر واقعی (مرورگر داخلی محیط توسعه اجازهٔ Service Worker نمی‌دهد).
- Lighthouse CI و Prettier؛ OpenTelemetry؛ رجیستری image قابل دسترس از ایران.
- به فاز مصرف‌کننده منتقل شد: FluentValidation و Antiforgery (فاز ۲، اولین فرم‌ها)، صف کارهای پس‌زمینه (فاز ۵/۷).

**معیار پایان:** `docker compose up` روی لینوکس و ویندوز صفحهٔ اصلی Next.js را با داده از API نشان دهد؛ CI سبز.

## فاز ۲ — هویت، نقش‌ها و حساب کاربری ✅

**تصمیم‌های ثبت‌شده**

| موضوع | تصمیم |
|---|---|
| شناسهٔ حساب | **ایمیل یا موبایل** (حداقل یکی، هر دو یکتا). موبایل به قالب بین‌المللی E.164 یکسان‌سازی می‌شود (منطقهٔ پیش‌فرض از تنظیمات فروشگاه). مدیر سیستم روش‌های ورود را روشن/خاموش می‌کند. |
| پیامک | رابط `ISmsSender` با **کاوه‌نگار، SMS.ir و Twilio**؛ پیش‌فرض **خاموش** (`NullSmsSender`). |
| مجوزها | **ثابت در کد:** هر نقش مجموعهٔ مشخصی از مجوزها؛ هر کارمند می‌تواند چند نقش داشته باشد؛ `Admin` همهٔ مجوزها را دارد. |
| ورود دومرحله‌ای | **اختیاری برای همه**؛ تنظیم `Security:RequireStaffTwoFactor` (پیش‌فرض خاموش) برای اجباری کردن در کارمندان. |
| نشست کاربر | کوکی Identity صادرشده توسط API (`HttpOnly`، `SameSite=Lax`، `Secure` در HTTPS) که از طریق proxy هم‌مبدأ Next.js به مرورگر می‌رسد؛ هیچ توکنی در JavaScript یا `localStorage` نیست. |
| CSRF | کوکی `SameSite=Lax` + فقط بدنهٔ JSON برای درخواست‌های تغییردهنده + بررسی هدر `Origin` در API (جایگزین Antiforgery کلاسیک که برای API مناسب نیست). |
| ایمیل | SMTP (MailKit) که با هر سرویس‌دهنده کار می‌کند؛ در Development ایمیل‌ها به‌صورت فایل `.eml` در پوشهٔ محلی ذخیره می‌شوند. |

**زیرمرحله‌ها**

- **۲الف ✅:** کاربر با ایمیل یا موبایل (یکتا، موبایل به E.164 و پذیرش ارقام فارسی/عربی)، مدل مجوزهای ثابت، کوکی ورود (`HttpOnly`/`SameSite=Lax`)، ثبت‌نام/ورود/خروج/«من کیستم»، تأیید ایمیل، فراموشی و بازنشانی رمز (پیوند یک‌بارمصرف ۲ ساعته؛ پایان سایر نشست‌ها)، قفل حساب پس از ۵ تلاش، سیاست رمز (حداقل ۸ کاراکتر + عدد؛ در ۱۴۰۵-۰۸-۱۸ از ۱۲ به ۸ کاهش یافت، همراه دکمهٔ نمایش/پنهان کردن رمز در همهٔ فرم‌ها)، FluentValidation با کدهای خطای ترجمه‌پذیر، بررسی `Origin`، محدودیت سخت‌تر نرخ برای endpointهای ورود، ایمیل چندزبانه (SMTP/فایل `.eml`)؛ صفحات ورود، ثبت‌نام، فراموشی/بازنشانی رمز، تأیید ایمیل و حساب کاربری در Next.js با هدایت امن پس از ورود؛ رفع قواعد `robots.txt` برای مسیرهای دارای پیشوند زبان.
- **۲ب ✅:** پیامک با کاوه‌نگار (Verify Lookup)، SMS.ir (Verify) و Twilio + حالت `Pickup` برای توسعه؛ **ورود و ثبت‌نام یکپارچه با کد پیامکی** (شمارهٔ جدید = ساخت حساب تأییدشده، بدون افشای ثبت‌شده بودن شماره)؛ حساب‌های موبایلی بدون رمز؛ ثبت‌نام با رمز فقط با ایمیل؛ افزودن موبایل تأییدشده به حساب ایمیلی؛ کد ۶ رقمی تصادفی امن، ذخیرهٔ فقط هش نمک‌دار، اعتبار ۳ دقیقه، ۵ تلاش، فاصلهٔ ۶۰ ثانیه، حداکثر ۵ کد در ساعت برای هر شماره (+ محدودیت IP)؛ قفل حساب با کد دور زده نمی‌شود؛ پرشدن خودکار کد در اندروید (WebOTP)؛ پذیرش ارقام فارسی/عربی؛ جلوگیری از ثبت کلید API در لاگ.
- **۲ج ✅:** ورود و ثبت‌نام با Google، Facebook و Microsoft (هر سرویس فقط وقتی کلیدش تنظیم شده نمایش داده می‌شود؛ در نسخهٔ ایران خالی)؛ اتصال خودکار به حساب موجود **فقط با ایمیل تأییدشده توسط Google** (جلوگیری از تصاحب حساب)، در غیر این صورت ورود و اتصال از صفحهٔ حساب؛ اتصال/جداسازی سرویس‌ها با منع حذف آخرین روش ورود؛ آدرس بازگشت OAuth از آدرس عمومی فروشگاه (PKCE، کوکی correlation با `SameSite=Lax`)؛ لغو یا پاسخ جعلی به صفحهٔ ورود با پیام ترجمه‌شده برمی‌گردد؛ دکمه‌های متنی بدون لوگو. ⚠️ ورود واقعی با هر سرویس هنوز با اپ واقعی آزموده نشده است.
- **۲د ✅:** ورود دومرحله‌ای اختیاری برای همه با برنامهٔ Authenticator (TOTP، کد QR در خود مرورگر ساخته می‌شود و کلید به هیچ سرویس بیرونی نمی‌رود)؛ ۱۰ کد بازیابی یک‌بارمصرف (نمایش فقط یک بار، دانلود، تجدید با کد)؛ «این دستگاه را به خاطر بسپار» و فراموش کردن دستگاه؛ مرحلهٔ دوم بعد از رمز، کد پیامکی و ورود با Google/Facebook/Microsoft؛ خاموش کردن فقط با کد فعلی؛ تنظیم `Security:RequireStaffTwoFactor` (پیش‌فرض خاموش) که دسترسی‌های کارکنان را به ورود دومرحله‌ای مشروط می‌کند.
- **۲هـ ✅:** صفحهٔ حساب با سه بخش (حساب، آدرس‌ها، حریم خصوصی)؛ ویرایش نام و زبان ایمیل/پیامک؛ تغییر رمز با رمز فعلی (خروج از دستگاه‌های دیگر)؛ **دفترچهٔ آدرس** (حداکثر ۲۰، یک آدرس پیش‌فرض، شماره به E.164 بر اساس کشور آدرس، اعتبارسنجی کد پستی ایران/ارمنستان/آلمان و…، پذیرش ارقام فارسی، حذف واقعی نه نرم، فقط کشورهای `Store:ShippingCountries`، بررسی مالکیت در خود کوئری)؛ **دانلود همهٔ اطلاعات شخصی** به‌صورت فایل JSON؛ **حذف حساب**: آدرس‌ها، سبد و کدهای پیامکی واقعاً حذف می‌شوند، ردیف کاربر بدون هیچ اطلاعات شخصی می‌ماند تا سفارش‌ها (سوابق مالی) سالم بمانند، همهٔ نشست‌ها باطل می‌شوند و ایمیل/شماره آزاد می‌شود؛ تأیید با رمز، یا برای حساب‌های بدون رمز ورود در ۱۰ دقیقهٔ اخیر (`Auth:ReauthenticationMinutes`)؛ کارمندان خودشان را حذف نمی‌کنند؛ تنظیم `Store:GuestCheckout` (پیش‌فرض روشن) در اطلاعات فروشگاه. رفع یک اشکال ۲د: بررسی دوره‌ای security stamp ادعای `amr=mfa` و زمان ورود را حذف می‌کرد. ⚠️ تغییر ایمیل هنوز نیست. ⚠️ وقتی سفارش‌ها آدرس و مشخصات تماس بگیرند (فاز ۵)، `PersonalDataService.DeleteAsync` باید آن‌ها را هم پاک کند.
- **۲و ✅:** اولین صفحات پنل مدیریت (`/{locale}/admin`: پوسته با بخش‌هایی که کاربر اجازه‌اش را دارد؛ کاربر بدون مجوز صفحهٔ ۴۰۴ می‌بیند و بازدیدکنندهٔ واردنشده به ورود هدایت می‌شود) و **مدیریت کارکنان** (فقط با مجوز `staff.manage`، یعنی مدیر کل):
  - **دعوت** با ایمیل یا شمارهٔ موبایل و یک یا چند نقش، معتبر ۷ روز. دعوت‌شده با همان ایمیل/شمارهٔ **تأییدشده** وارد می‌شود (یا حساب می‌سازد) و دعوت را در صفحهٔ حساب می‌پذیرد؛ نقش‌ها بلافاصله اعمال می‌شوند. برای ایمیل، پیام دعوت (۵ زبان) هم فرستاده می‌شود؛ برای موبایل پیامک ارسال نمی‌شود (قالب‌های پیامک فقط کد یک‌بارمصرف‌اند) و مدیر خودش خبر می‌دهد. لغو دعوت؛ دعوت تکراری یا برای کسی که از قبل کارمند است رد می‌شود.
  - **تغییر نقش‌ها**، **تعلیق/فعال‌سازی دوباره** (حساب معلق با هیچ روشی وارد نمی‌شود و نشست‌های بازش ظرف یک دقیقه بسته می‌شوند) و **حذف از کارکنان** (حساب به‌عنوان مشتری باقی می‌ماند). کسی روی حساب خودش این کارها را نمی‌کند و فروشگاه همیشه حداقل یک مدیر کل فعال دارد.
  - **گزارش تغییرات** (چه کسی، چه کاری، روی چه کسی، چه زمانی) برای همهٔ دعوت‌ها و تغییرات.
  - بررسی دوره‌ای نشست (security stamp) از ۳۰ دقیقه به **۱ دقیقه** کاهش یافت تا تعلیق و تغییر نقش سریع اعمال شود؛ تغییر نقش کاربر را از حساب خارج نمی‌کند و فقط دسترسی‌هایش ظرف یک دقیقه به‌روز می‌شود.
  - مقادیر enum در API به‌صورت متن (`"Pending"`) فرستاده می‌شوند نه عدد.
  - رفع یک اشکال قدیمی: آدرسی که بخش اولش زبان نبود (مثل `/favicon.png`) به‌جای ۴۰۴ خطای ۵۰۰ می‌داد.
  - ⚠️ پیام ورود حساب معلق همان «قفل شده» است (برای جلوگیری از افشای وضعیت حساب)؛ پاک‌سازی خودکار دعوت‌های منقضی هنوز نیست.

## فاز ۳ — چندزبانگی، تم، سیستم طراحی و PWA ✅

- زبان‌ها: **fa، en، hy، de، ar**؛ افزودن زبان جدید = یک فایل پیام در Next.js + یک ردیف در تنظیمات.
- متن رابط کاربری با دیکشنری‌های JSON خود پروژه (`src/lib/i18n/dictionaries`، یک تست هم‌خوانی کلیدها را در هر پنج زبان بررسی می‌کند) به‌جای `next-intl`، چون بدون وابستگی اضافه همان نیاز را برآورده می‌کند؛ محتوای پایگاه داده با جدول‌های ترجمه و Fallback به زبان پیش‌فرض؛ مسیر `/{locale}/…` و `hreflang`.
- RTL برای fa/ar، LTR برای بقیه؛ تاریخ شمسی برای fa؛ قالب عدد و ارز بر اساس زبان.
- **تم روشن و تیره** (پیش‌فرض بر اساس سیستم، قابل تغییر و ذخیره، بدون چشمک هنگام بارگذاری).
- سیستم طراحی مستقل (Tailwind CSS + کامپوننت‌های خودمان)، Skeleton loading، انیمیشن‌های سبک.
- **قالب‌ها و برند:** توکن‌های طراحی (رنگ، فونت، گردی گوشه‌ها) از پنل؛ لوگو و بنرها؛ چند قالب چیدمان آماده برای صفحهٔ اصلی و لیست محصولات (انتخاب از پنل، بدون نیاز به build دوباره).
- همهٔ فونت‌ها و آیکون‌ها self-hosted (Vazirmatn برای فارسی/عربی، فونت OFL با پشتیبانی ارمنی برای hy).
- مسیرهای همیشه با پیشوند زبان، `hreflang` فقط برای زبان‌های ترجمه‌شده + `x-default`، قالب عنوان/توضیحات برای هر زبان ([SEO-MARKETING](SEO-MARKETING.md) بندهای ۲ تا ۴).
- **Mobile-first**: نوار پایین موبایل، منوی کشویی، لمس‌پذیری؛ PWA نصب‌پذیر با صفحهٔ آفلاین.

**زیرمرحله‌ها**

- **۳الف ✅:** سیستم طراحی و تم.
  - توکن‌های طراحی کامل: رنگ‌های پایه، حالت‌ها (خطا، موفقیت، هشدار)، حلقهٔ فوکوس، و یک `--radius` پایه که همهٔ گردی‌ها از آن ساخته می‌شوند. آمادهٔ تغییر از پنل در ۳د.
  - **تم روشن/تیره/مطابق سیستم** با دکمه در سربرگ، ذخیره در همان دستگاه، و همگام بین تب‌ها. اسکریپت کوچکی در `<head>` تم را پیش از اولین نقاشی صفحه اعمال می‌کند: بدون چشمک، و صفحات همچنان از پیش ساخته (prerender) می‌مانند. بدون JavaScript تنظیم سیستم اعمال می‌شود.
  - **فونت‌های self-hosted (OFL) از npm با `next/font/local`:**
    - Vazirmatn فقط برای حروف فارسی/عربی (`unicode-range`) و اولِ همهٔ زبان‌ها، تا محتوای ترجمه‌نشدهٔ فارسی در صفحات دیگر هم درست نمایش داده شود.
    - Inter برای لاتین و Noto Sans Armenian برای ارمنی.
    - مرورگر فقط فونت‌هایی را دانلود می‌کند که حروفشان در صفحه هست (در مرورگر بررسی شد).
  - کامپوننت‌های پایه: `Button`/`ButtonLink`/`buttonClass`، `Card`، `Badge`، `Skeleton`. فوکوس صفحه‌کلید همیشه دیده می‌شود، و برای کسانی که «حرکت کمتر» خواسته‌اند انیمیشن حذف می‌شود.
- **۳ب ✅:** چیدمان mobile-first بر اساس طرح «طراحی صفحه اول فروشگاه» (ساختار الهام‌گرفته از دیجی‌کالا، با پالت، آیکون‌ها و متن‌های خودمان).
  - **سربرگ چسبان:** نشان (حرف اول نام فروشگاه تا آپلود لوگو در ۳د) و نام، کادر جستجو (فرم GET به `/{locale}/search`، بدون JavaScript هم کار می‌کند)، پوسته، انتخاب زبان، ورود/حساب و سبد خرید؛ در دسکتاپ ردیف منوی اصلی. در موبایل جستجو تمام‌عرض زیر نام است و حساب و سبد در نوار پایین‌اند.
  - **نوار پایین موبایل:** خانه، دسته‌بندی، سبد خرید، حساب من (تب فعال با `aria-current`)؛ در پنل مدیریت نمایش داده نمی‌شود.
  - **انتخاب زبان:** همان صفحه در زبان دیگر، فقط زبان‌های فعال فروشگاه؛ با `<details>` و بدون JavaScript هم باز می‌شود. پاورقی هم پیوند هر زبان را دارد.
  - **پاورقی تیره:** دربارهٔ فروشگاه، پیوندهای خرید و حساب، زبان‌ها و سطر حق نشر با سال به تقویم همان زبان (۱۴۰۵ برای fa).
  - **صفحهٔ اصلی:** بنر خوشامد (h1 = نام فروشگاه)، دسترسی سریع، کاشی‌های دسته‌بندی (`#categories`)، مزایای خرید.
  - توکن‌های تازه: `accent` (نشان‌ها و تخفیف)، `inverse` (نوار تیره)، و رنگ‌های ملایم `tint tint-0…7` که در هر دو پوسته کار می‌کنند. آیکون‌های خطی خودمان در `components/ui/Icon.tsx`.
  - صفحه‌های موقت **جستجو** و **سبد خرید** (noindex) تا فاز ۶ و ۷، تا پیوندهای سربرگ و نوار پایین به صفحهٔ خالی نروند.
  - ⚠️ عمداً مانده: ردیف‌های کالا در طرح (پیشنهاد لحظه‌ای با شمارش معکوس، پرفروش‌ترین‌ها، پیشنهاد برای شما) به فاز ۶ و داده‌های واقعی کالا؛ بنرهای تبلیغاتی و نوار اطلاع‌رسانی بالای صفحه به ۳د؛ «خواندنی‌ها» به بلاگ؛ منوی کشویی دسته‌ها و پیوند کاشی‌ها به صفحهٔ دسته در فاز ۶. هیچ دادهٔ نمونهٔ ساختگی در فروشگاه نمایش داده نمی‌شود.
- **۳ج ✅:** قالب عدد، ارز و تاریخ بر اساس زبان (پول همیشه با ارز)؛ جدول‌های ترجمه برای محتوای پایگاه داده (دسته‌ها) با Fallback و `hreflang` فقط برای زبان‌های ترجمه‌شده.
  - ✅ **انجام‌شده (همراه با کاتالوگ نمونه):**
    - جدول‌های ترجمه برای دسته، زیردسته، گروه محصول، محصول، ویژگی و گزینهٔ ویژگی. زبان پیش‌فرض در ستون‌های خود ردیف می‌ماند و بقیهٔ زبان‌ها در جدول ترجمه.
    - API دسته‌ها با `?locale=`، با Fallback به زبان پیش‌فرض، و مرتب‌سازی به الفبای همان زبان.
    - تنظیم ارز پایهٔ فروشگاه: `Store:Currency`.
  - ✅ **ارزهای نمایشی و مبدل ارز:**
    - **انتخاب ارز در سربرگ:** کنار انتخاب زبان. انتخاب مشتری در کوکی و همراه با زبانش ذخیره می‌شود.
    - **ارز پیش‌فرض هر زبان:** پس از تغییر زبان، ارز پیش‌فرض همان زبان دیده می‌شود: fa ← IRR، en ← USD، de ← EUR، hy ← AMD، ar ← AED.
    - **قیمت‌ها:** همیشه به ارز پایه ذخیره می‌شوند و فقط برای نمایش تبدیل و با گام هر ارز گرد می‌شوند. درصد تخفیف از قیمت پایه حساب می‌شود. در صفحهٔ محصول یادآوری «قیمت تقریبی؛ پرداخت به ارز پایه» نشان داده می‌شود.
    - **JSON-LD:** همان قیمت و ارزِ نمایش‌داده‌شده را دارد. برای ارز غیر ISO مثل تومان (IRT)، قیمت پایه را نگه می‌دارد.
    - **بخش «واحدهای پول» در پنل** (دسترسی settings.manage):
      - افزودن ارز: کد ISO، یا ارز تعریف‌شدهٔ فروشگاه مثل IRT با نماد «تومان».
      - نماد، رقم اعشار، گام گرد کردن، نرخ، فعال/غیرفعال و ترتیب.
      - ارز پیش‌فرض هر زبان، و دکمهٔ «به‌روزرسانی نرخ‌ها».
    - **نرخ خودکار (اختیاری):** `ExchangeRates:Provider=CurrencyApi` (fawazahmed0/exchange-api: رایگان، بدون کلید، داده با مجوز CC0، با آدرس جایگزین).
      - یک کار پس‌زمینه هر ۱۲ ساعت نرخ ارزهایِ «خودکار» را به‌روز می‌کند.
      - صفحه‌ها هرگز این سرویس را صدا نمی‌زنند. اگر سرویس در دسترس نباشد (مثلاً روی سرور ایران)، آخرین نرخ‌ها می‌مانند و مدیر می‌تواند نرخ را دستی وارد کند.
      - این تنها استثنای قاعدهٔ «بدون وابستگی به سرویس بیرونی» است و با `None` خاموش می‌شود.
  - ⬜ **مانده (به فاز ۶ منتقل شد):** `hreflang` صفحهٔ دسته‌ها، همراه با خود صفحه‌های دسته.
- **کاتالوگ نمونه برای دموی فروشگاه ✅:**
  - **چه چیزی اضافه می‌شود:**
    - ۴ دسته، ۱۲ زیردسته و ۲۲ محصول.
    - برندهای ساختگی (Orvia، Casana، Ranna، Papira).
    - همهٔ متن‌ها به پنج زبان، دستی نوشته‌شده.
    - ۲۶ ویژگی تایپ‌دار (عدد با واحد، بله/خیر، گزینهٔ ترجمه‌شده، متن).
    - قیمت و قیمت قبل از تخفیف (نوشته‌شده به یورو، تبدیل‌شده به ارز فروشگاه)، و موجودی.
    - تصویرسازی SVG خودمان برای هر محصول و دسته.
  - **روشن‌کردن:** با `DemoCatalog:Enabled`؛ در Development روشن است و روی سرور دمو با `DEMO_CATALOG=true`. فقط یک بار و فقط به فروشگاهی که هنوز کالای نمونه ندارد اضافه می‌شود.
  - **پیش‌درآمدی از فاز ۴:** مدل ویژگی‌ها (`product_specs`، `spec_options`، `product_spec_values`)، `public_number` و slug هر زبان.
  - ✅ **نمایش محصولات:**
    - API عمومی محصولات: فهرست‌های «تخفیف‌دار» و «جدیدترین»، جزئیات یک محصول، و slug هر زبان.
    - ردیف «پیشنهادهای ویژه» (نوار رنگی با اسکرول افقی) و «جدیدترین کالاها» در صفحهٔ اول.
    - صفحهٔ محصول `/{locale}/p/{number}/{slug}`: مسیر صفحه، تصویر، ویژگی‌های اصلی، جعبهٔ قیمت با درصد تخفیف و موجودی، معرفی، و جدول مشخصات گروه‌بندی‌شده.
    - SEO صفحهٔ محصول:
      - canonical؛ و hreflang فقط برای زبان‌های ترجمه‌شده (صفحهٔ ترجمه‌نشده noindex است و canonical آن به زبان پیش‌فرض می‌رود).
      - JSON-LD از نوع Product/Offer با همان قیمت و موجودیِ نمایش‌داده‌شده.
      - 301 برای slug قدیمی، اشتباه یا جاافتاده (در proxy).
    - قالب پول با `Intl`: مبلغ و بعد ارز در fa/ar، با ارقام همان زبان.
  - ⚠️ **مانده:**
    - دکمهٔ «افزودن به سبد» تا فاز ۷ غیرفعال است.
    - «پرفروش‌ترین‌ها» به سفارش واقعی نیاز دارد.
    - شمارش معکوس پیشنهادها به تاریخ پایان پیشنهاد نیاز دارد.
    - محصولات هنوز در Sitemap نیستند.
    - BreadcrumbList در JSON-LD به صفحهٔ دسته (فاز ۶) وابسته است.
    - محصولِ ناموجود 404 «نرم» است (noindex داخل صفحه)، نه وضعیت HTTP 404.
- **۳د ✅:** برند و قالب‌ها از پنل («ظاهر فروشگاه»، دسترسی settings.manage)، اعمال در زمان اجرا بدون build دوباره.
  - **رنگ اصلی:** در پوستهٔ روشن و تیره اعمال می‌شود و رنگ متن روی آن خودکار و خوانا انتخاب می‌شود. فقط قالب `#rrggbb` پذیرفته می‌شود تا هیچ متن دیگری وارد CSS نشود.
  - **گردی گوشه‌ها:** تیز، نرم یا گرد.
  - **فونت:** وزیرمتن یا فونت دستگاه کاربر.
  - **سه قالب چیدمان صفحهٔ اول:** کلاسیک، کاتالوگ (اول دسته‌بندی‌ها، بدون بنر) و ویترین.
  - پس از ذخیره، کش فروشگاه بلافاصله پاک می‌شود (مسیر `/{locale}/admin/refresh`، فقط برای مدیر واردشده و فقط از خود سایت).
  - لوگو و تصویر بنر در ۴ب اضافه شد.
- **۳ه ✅:** تکمیل PWA.
  - **کارت «نصب وب‌اپ» در پاورقی:** با دکمهٔ نصب در مرورگرهایی که پشتیبانی می‌کنند، و راهنمای «اشتراک‌گذاری ← افزودن به صفحهٔ اصلی» در Safari آیفون.
  - کارت در حالت نصب‌شده نمایش داده نمی‌شود و اگر کاربر آن را ببندد، دیگر نشان داده نمی‌شود.
  - **manifest در زمان اجرا:** نام فروشگاه، زبان پیش‌فرض و رنگ اصلیِ برند.
  - ⚠️ رفتار Service Worker و نصب را باید در یک مرورگر واقعی آزمود.

## فاز ۴ — کاتالوگ محصولات ✅

**زیرمرحله‌ها**

- **۴الف ✅:** پنل مدیریت کاتالوگ (دسترسی catalog.manage؛ صفحه‌های «کالاها» و «دسته‌بندی‌ها»).
  - **دسته‌بندی‌ها:** درخت دسته ← زیردسته ← گروه کالا، با نام و slug هر زبان (slug خالی از روی نام ساخته می‌شود و یکتاست). حذف نرم، فقط برای موارد خالی.
  - **محصول:**
    - ایجاد، ویرایش، انتشار و حذف نرم.
    - شمارهٔ عمومی خودکار؛ شمارهٔ کالای حذف‌شده هرگز دوباره استفاده نمی‌شود.
    - SKU یکتا؛ قیمت، قیمت قبل از تخفیف (باید بیشتر از قیمت باشد) و موجودی. عددها با ارقام فارسی، جداکننده یا ممیز هم پذیرفته می‌شوند.
  - **ترجمهٔ دستی:** نام، slug و توضیحات برای هر زبان فعال. زبانِ خالی «ترجمه‌نشده» نشان داده می‌شود و فروشگاه برای آن زبان متن پیش‌فرض را نشان می‌دهد.
  - **فهرست کالاها:** جستجو با نام (در هر زبان)، SKU یا شماره، صفحه‌بندی، و نشان پیش‌نویس، ناموجود و زبان‌های ترجمه‌نشده.
  - **مشخصات:** مقدار ویژگی‌های موجود با کنترل نوع (عدد با واحد، بله/خیر، گزینه، متن). مقدار خالی یعنی حذف آن ویژگی.
  - پس از هر ذخیره، کش فروشگاه بلافاصله پاک می‌شود.
  - ⚠️ تعریف ویژگی‌ها و گزینه‌های تازه در پنل در ۴ج می‌آید (تصویرها در ۴ب اضافه شد).
- **۴ب ✅:** ذخیره‌سازی فایل و تصاویر.
  - **`IFileStorage`:** روی دیسک محلی (`Storage:LocalPath`، پیش‌فرض `App_Data/media`؛ در Docker روی volume با نام `media`). مسیری که از پوشهٔ ریشه بیرون برود رد می‌شود.
  - **امنیت آپلود:**
    - نوع فایل از روی Magic bytes تشخیص داده می‌شود (JPEG، PNG، WebP و GIF)، نه از روی نام یا Content-Type.
    - محدودیت حجم (`Media:MaxUploadBytes`، پیش‌فرض ۱۰ مگابایت) و محدودیت پیکسل که پیش از decode از روی سرآیند بررسی می‌شود (`Media:MaxPixels`).
    - تصویر همیشه با SkiaSharp از نو ساخته می‌شود، پس متادیتا (EXIF، موقعیت مکانی) و هر محتوای پنهان یا اسکریپتِ چسبیده به فایل حذف می‌شود. جهت EXIF پیش از حذف اعمال می‌شود.
  - **WebP در سه اندازه:** ۱۲۰۰، ۶۰۰ و ۳۰۰ پیکسل، بدون بزرگ‌کردن تصویر کوچک.
    - نشانی: `/api/v1/media/{key}/{size}.webp`، با کش یک‌ساله و `immutable`. کلید هر تصویر تازه است و هرگز دوباره به کار نمی‌رود.
  - **تصاویر محصول:** حداکثر ۱۲ تصویر؛ آپلود چندتایی، ترتیب (اولی تصویر اصلی است)، حذف، و متن جایگزین هر زبان با بازگشت به زبان پیش‌فرض.
    - در فروشگاه: گالری با تصاویر کوچک، تصویر ۶۰۰ در کارت‌ها، و تصویر ۱۲۰۰ در og:image و JSON-LD.
  - **تصویر دسته؛ لوگو و بنر صفحهٔ اول (۳د):** از پنل آپلود یا حذف می‌شوند، و فایل‌های قبلی پاک می‌شوند. فروشگاه فقط نشانی‌های رسانهٔ خودِ API را می‌پذیرد.
  - ⚠️ ذخیره‌سازی S3-compatible (مثلاً MinIO) فقط یک پیاده‌سازی دیگر از `IFileStorage` است و هر وقت فروشگاهی لازمش داشت اضافه می‌شود.
- **۴ج ✅:** برند، کتابخانهٔ ویژگی‌ها با قالب هر دسته، و تنوع محصول (رنگ و سایز).
  - **برندها** (صفحهٔ «برندها»):
    - نام، نامک و توضیح هر زبان، و لوگو (۳۰۰ پیکسل).
    - برندی که کالا دارد حذف نمی‌شود.
    - در صفحهٔ کالا و JSON-LD نمایش داده می‌شود. ویژگی متنی قدیمی `brand` فقط برای داده‌های قبلی پشتیبانی می‌شود.
  - **کتابخانهٔ ویژگی‌ها** (صفحهٔ «ویژگی‌ها»):
    - هر ویژگی: نوع، پرچم‌های فیلتر/مقایسه/ویژگی اصلی، و نام، گروه و واحد هر زبان. ترتیب ویژگی‌ها همین‌جا تعیین می‌شود.
    - گزینه‌ها هم ترجمهٔ هر زبان را دارند.
    - کد لاتین ویژگی و گزینه اگر خالی بماند از روی نام ساخته می‌شود، و برای نام غیرلاتین به‌صورت `spec_1` و `option_1`.
    - نوع ویژگیِ در حال استفاده ثابت است. ویژگی یا گزینهٔ در حال استفاده حذف نمی‌شود.
  - **قالب ویژگی:**
    - هم دسته و هم زیردسته قالب دارند؛ قالب زیردسته به قالب دسته اضافه می‌شود.
    - ویرایشگر کالا ویژگی‌های قالب را با تغییر گروه کالا خودکار نشان می‌دهد. ویژگی‌های دیگر هم قابل افزودن‌اند.
  - **تنوع‌ها:**
    - هر کالا بر اساس حداکثر سه ویژگیِ «انتخاب از فهرست» تنوع دارد و حداکثر ۱۰۰ تنوع.
    - هر تنوع SKU و موجودی خودش را دارد، و قیمت و قیمت قبل از تخفیف اختیاری (خالی یعنی قیمت کالا).
    - ترکیب تکراری مجاز نیست. SKU بین کالاها و تنوع‌ها یکتاست.
    - ویژگیِ تنوع نمی‌تواند مقدار سطح کالا هم داشته باشد.
    - موجودی کالا جمع موجودی تنوع‌هاست. تنوع حذف‌شده به‌صورت نرم حذف می‌شود، چون سفارش‌های فاز ۷ به آن اشاره خواهند کرد.
    - **در فروشگاه:** انتخاب رنگ و سایز در کادر قیمت.
      - تنوع پیش‌فرض (اولین موجود) سمت سرور رندر می‌شود و بدون JavaScript هم درست است.
      - گزینه‌ای که با انتخاب‌های دیگر ناموجود است خط‌خورده نشان داده می‌شود.
    - **JSON-LD:** `ProductGroup` با `variesBy` (رنگ، سایز، جنس) و یک `Product` با Offer خودش برای هر تنوع، با همان قیمت تبدیل‌شده‌ای که صفحه نشان می‌دهد.
  - **دادهٔ نمونه:**
    - چهار برند و قالب هر زیردسته از روی ویژگی‌های کالاهایش.
    - هودی با ۸ تنوع (۲ رنگ × ۴ سایز).
  - ⚠️ عکس جداگانه برای هر تنوع و انتخاب تنوع در سبد خرید (فاز ۷) بعداً می‌آیند.
- **۴د ✅:** فیلدهای SEO و جستجو.
  - **کدهای کالا:**
    - **بارکد (GTIN):** ۸، ۱۲، ۱۳ یا ۱۴ رقم با رقم کنترل درست. ارقام فارسی، فاصله و خط تیره هم پذیرفته می‌شوند. هر تنوع هم می‌تواند بارکد خودش را داشته باشد.
    - MPN و وزن (گرم).
    - هر سه در JSON-LD می‌آیند (`gtin`، `mpn`، `weight`) و پایهٔ فیدهای خرید هستند.
  - **متن‌های جستجوی هر زبان:**
    - عنوان، توضیح و کلمه‌های جستجو (برچسب‌ها)، روی ستون‌های کالا و جدول ترجمه. خالی یعنی نام و ابتدای توضیحات کالا.
    - زبانی که نامش ترجمه نشده متن جستجو هم ندارد، چون صفحه‌اش noindex است.
  - **پیش‌نمایش نتیجهٔ جستجو در ویرایشگر کالا:** همان‌طور که تایپ می‌شود، به‌روز می‌شود.
    - هشدار برای عنوان بلندتر از ۶۰ نویسه، و برای توضیحی که نیست، کوتاه‌تر از ۷۰ یا بلندتر از ۱۶۰ نویسه است.
    - هشدار برای کالای بی‌تصویر، تصویر بی‌متن جایگزین، و زبان ترجمه‌نشده.
  - **مترادف‌های جستجو** (صفحهٔ «سئو»):
    - گروه کلمه‌ها برای هر زبان، که یکسان‌سازی‌شده ذخیره می‌شوند (`SearchText`: «ي/ك»، ارقام، نیم‌فاصله، اعراب و حروف کوچک). همین یکسان‌سازی در جستجوی فاز ۶ هم به کار می‌رود.
    - هر کلمه در هر زبان فقط در یک گروه می‌آید.
  - **جدول `redirects`** (صفحهٔ «سئو»):
    - انواع: 301، 302 و 410.
    - ورود گروهی از CSV؛ آدرس کامل سایت قبلی، query و آدرس فارسی هم پذیرفته می‌شوند.
    - آدرس قدیمی نمی‌تواند صفحهٔ اصلی، `/api` یا `/_next` باشد. حلقه و زنجیرهٔ تغییر مسیر هم مجاز نیست (همیشه یک گام).
    - `proxy.ts` جدول را یک دقیقه در حافظه نگه می‌دارد. پس تغییرات تا یک دقیقه بعد اعمال می‌شوند، و اگر API در دسترس نباشد سایت بدون تغییر مسیر کار می‌کند.
    - تعداد و زمان آخرین استفاده پس از پاسخ ثبت می‌شود.
    - آدرس کالاها شمارهٔ ثابت دارند و slug اشتباه از قبل 301 می‌شود.
  - ⚠️ گزارش 404ها (`not_found_log`) و ساخت خودکار تغییر مسیر هنگام تغییر نامک دسته (وقتی صفحهٔ دسته در فاز ۶ بیاید) هنوز مانده‌اند. فیلدهای متای دسته و برند در مدل هست ولی در پنل نه.
- **۴ه ✅:** ورود و خروج گروهی محصولات و موجودی با CSV/Excel (صفحهٔ «ورود و خروج گروهی»).
  - **خروجی:**
    - Excel با کتابخانهٔ MiniExcel (مجوز Apache-2.0، بدون وابستگی دیگر؛ ClosedXML به‌خاطر مجوز SixLabors.Fonts کنار گذاشته شد).
    - CSV با BOM، تا Excel فارسی را درست نشان دهد.
    - **ستون‌های فایل کالاها:**
      - `number`، `sku`، `published`، `group` («دسته > زیردسته > گروه»)، `brand`، `price`، `compare_at_price`، `stock`، `gtin`، `mpn`، `weight_grams`.
      - برای هر زبان: `name`، `slug`، `description`، `meta_title`، `meta_description` و `tags` (مثل `name:fa`).
      - یک ستون `spec:کد` برای هر ویژگی در حال استفاده.
    - **فایل موجودی:** `sku` و `stock` برای هر کالای بدون تنوع و هر تنوع.
  - **ورود:**
    - **تطابق ردیف‌ها:** ردیف با `number` یا SKU پیدا می‌شود؛ بدون تطابق، کالای تازه ساخته می‌شود.
    - **فقط ستون‌های موجود عوض می‌شوند:** فایلی با `sku,price` فقط قیمت را عوض می‌کند. خانهٔ خالی ویژگی، آن مقدار را حذف می‌کند.
    - **ساخت خودکار:** دسته، زیردسته، گروه و برندِ تازه با نام ساخته می‌شوند. گزینهٔ ویژگی با کد یا نامش در هر زبان پیدا می‌شود.
    - **قالب داده:** ارقام فارسی و عربی، جداکنندهٔ هزارگان و بله/خیر به هر پنج زبان پذیرفته می‌شوند.
    - **قواعد مشترک:** هر ردیف از همان قواعد ویرایشگر کالا می‌گذرد (SKU یکتا، بارکد، تنوع‌ها و…).
  - **همه یا هیچ:**
    - فایل در یک تراکنش اعمال می‌شود؛ هر ردیف یک savepoint دارد.
    - با یک مشکل یا در حالت «بررسی»، هیچ چیز ذخیره نمی‌شود.
    - گزارش، شمارهٔ ردیف، ستون و پیام ترجمه‌شده را نشان می‌دهد. دکمهٔ «ورود» فقط پس از بررسیِ بی‌مشکل همان فایل فعال می‌شود.
  - **موجودی:** با SKU کالا یا تنوع. موجودی کالای دارای تنوع جمع تنوع‌هایش می‌شود.
  - **محدودیت‌ها:** ۱۰ مگابایت و ۵۰۰۰ ردیف؛ ستون ناشناخته یا تکراری پیش از هر ردیف گزارش می‌شود.
  - ⚠️ ساخت و ویرایش تنوع‌ها و تصاویر با فایل در این مرحله نیست (تنوع‌ها از ویرایشگر کالا ساخته می‌شوند؛ موجودی‌شان از فایل).
- **۴و ✅:** ویدئوی محصول (کارت «ویدئوها» در ویرایشگر کالا).
  - **قالب و محدودیت:** تا ۳ ویدئوی MP4 برای هر کالا، هرکدام حداکثر ۵۰ مگابایت (`Media:MaxVideoBytes`).
  - **بررسی فایل:**
    - ساختار جعبه‌های MP4 خوانده می‌شود: جعبهٔ `ftyp` با برند MP4 و جعبهٔ `moov`. فایل MOV کوئیک‌تایم، فایل خراب و فایل تغییرنام‌یافته رد می‌شوند.
    - مدت از `mvhd` خوانده می‌شود.
    - فایل تبدیل نمی‌شود و همان‌طور که هست ذخیره می‌شود. با `video/mp4` و `nosniff` سرو می‌شود، پس مرورگر آن را جز ویدئو اجرا نمی‌کند.
  - **پخش:**
    - پخش با Range request (پاسخ 206، برای جلو و عقب رفتن) از همان آدرس رسانه، با کش یک‌ساله.
    - در گالری فروشگاه پس از تصاویر می‌آید. فقط با زدن پخش بارگیری می‌شود (`preload="none"`) و هرگز خودکار پخش نمی‌شود.
  - **تصویر پیش از پخش و عنوان:** تصویر اختیاری است (مثل هر تصویر، بازسازی‌شده) و بدون آن تصویر اصلی کالا نشان داده می‌شود. عنوان برای هر زبان جداست.
  - **آپلود:** با نوار پیشرفت. سقف بدنهٔ درخواست در `proxy.ts` (`proxyClientMaxBodySize`، پیش‌فرض Next.js ده مگابایت) و در nginx به ۵۲ مگابایت رسید.
  - **JSON-LD:** `VideoObject` در `subjectOf` کالا، با `contentUrl`، `thumbnailUrl`، `uploadDate` و `duration`.
  - ⚠️ پیش از آپلود، ویدئو را فشرده کنید (مثلاً ۷۲۰p با H.264). متادیتای داخل فایل (مثل موقعیت مکانی دوربین) حذف نمی‌شود، چون تبدیل فرمت در نسخهٔ ۱ نیست. Sitemap ویدئو در فاز ۶ می‌آید.

- دسته‌بندی درختی، برند، ویژگی‌ها و مشخصات فنی قابل فیلتر، تنوع محصول (رنگ/سایز).
- **مدل دادهٔ ویژگی‌ها (پایهٔ جستجو، فیلتر و مقایسه):**
  - هر دسته یک **قالب ویژگی** دارد (گروه‌ها مثل «صفحه‌نمایش» و «حافظه»، ترتیب نمایش، واحد).
  - نوع هر ویژگی: متنی، عددی با واحد، بله/خیر، یا انتخاب از فهرست مقادیر ترجمه‌شده. هر ویژگی پرچم «قابل فیلتر»، «قابل مقایسه» و «در خلاصهٔ محصول» دارد.
  - مقادیر در جدول جداگانهٔ `product_attribute_values` ذخیره می‌شوند: مقدار عددی در ستون عددی و انتخاب‌ها با شناسهٔ گزینه. ایندکس‌ها برای فیلتر و شمارش (facet) سریع طراحی می‌شوند؛ متن آزاد داخل JSON فیلترپذیر نیست.
  - ویژگی‌های سطح تنوع (رنگ، سایز) از ویژگی‌های سطح محصول جدا هستند.
- فیلدهای جستجو در مدل: نام‌ها و برچسب‌های هر زبان، SKU، GTIN/بارکد، `public_number`. **مترادف‌ها** هم از پنل مدیریت می‌شوند (جدول `search_synonyms`، برای هر زبان؛ مثلاً «گوشی = موبایل = تلفن همراه»).
- **چند تصویر و ویدئو برای هر محصول** پشت `IFileStorage` (دیسک محلی / S3-compatible)؛ امنیت آپلود (Magic bytes، حجم، بازسازی تصویر)؛ WebP/AVIF و اندازه‌های مختلف.
- پنل مدیریت محصولات در Next.js؛ ترجمهٔ دستی هر فیلد برای زبان‌های فعال با نمایش «ترجمه‌نشده».
- **ورود و خروج گروهی محصولات و موجودی با CSV/Excel** (برای راه‌اندازی سریع فروشگاه‌هایی که از جای دیگر می‌آیند).
- فیلدهای SEO در مدل ([SEO-MARKETING](SEO-MARKETING.md) «اثر روی مدل داده»): `public_number`، GTIN/MPN، وزن، slug و متای هر زبان، متن جایگزین تصویر؛ جدول `redirects` با 301 خودکار هنگام تغییر slug؛ پیش‌نمایش نتیجهٔ گوگل و هشدارهای SEO در پنل.
- ویدئو: MP4 با محدودیت حجم، پخش با Range request؛ بدون تبدیل فرمت در نسخهٔ ۱. ذخیره‌سازی پیش‌فرض دیسک محلی؛ S3-compatible اختیاری (در ایران مثلاً فضای ابری داخلی).

## فاز ۵ — انبارداری و انبارگردانی ✅

- انبار(ها)، دفتر حرکات کالا (ورود، خروج، فروش، مرجوعی، تعدیل، انتقال)؛ موجودی = جمع حرکات.
- رزرو موجودی هنگام پرداخت؛ جلوگیری از فروش بیش از موجودی.
- **انبارگردانی:** دورهٔ شمارش، ثبت شمارش، گزارش مغایرت، سند تعدیل.
- هشدار حداقل موجودی، تأمین‌کنندگان، رسید خرید، بهای تمام‌شده (میانگین موزون).

**زیرمرحله‌ها**

- **۵الف ✅:** انبارها و دفتر حرکات کالا.
  - **انبارها** (صفحهٔ «انبارها»، مجوز inventory.view؛ تغییر با inventory.manage):
    - هر فروشگاه همیشه دقیقاً یک انبار پیش‌فرضِ فعال دارد. فروشگاه تازه «انبار اصلی» را به زبان پیش‌فرض خودش می‌گیرد.
    - کد لاتین اگر خالی بماند از روی نام ساخته می‌شود. نام انبار فقط برای کارکنان است و ترجمه نمی‌شود.
    - انباری که موجودی دارد غیرفعال نمی‌شود. انباری که حرکت داشته حذف نمی‌شود، فقط غیرفعال می‌شود.
  - **دفتر حرکات** (جدول `stock_movements`):
    - هر سطر: انبار، کالا یا تنوع، نوع (موجودی اول، ورود، خروج، فروش، مرجوعی، تعدیل، انتقال خروج/ورود)، تعداد علامت‌دار، مانده پس از حرکت، شمارهٔ سند، توضیح و کاربر.
    - سطرها هرگز ویرایش یا حذف نمی‌شوند. اشتباه با یک حرکت تازه اصلاح می‌شود.
  - **موجودی = جمع حرکات:**
    - موجودی هر کالا در هر انبار (`stock_levels`) و موجودی کل کالا و تنوع فقط با `StockLedger` تغییر می‌کنند، همیشه همراه یک سطر دفتر.
    - هر تغییر یک UPDATE اتمی است («موجودی + n» به شرط منفی نشدن)، پس دو حرکت هم‌زمان هم را گم نمی‌کنند و بیش از موجودی برداشته نمی‌شود. محدودیت `quantity >= 0` در پایگاه داده هم هست.
    - موجودی فروشگاه جمع همهٔ انبارهاست؛ ویترین مثل قبل همان عدد را می‌خواند.
  - **ویرایش کالا، تنوع‌ها و ورود گروهی** همچنان عدد موجودی را می‌گیرند، ولی تغییرشان یک سطر «تعدیل» در دفتر می‌شود:
    - افزایش به انبار پیش‌فرض می‌رود. کاهش اول از انبار پیش‌فرض و بعد از انبارهای دیگر برداشته می‌شود.
    - تنوع حذف‌شده، و موجودی خودِ کالایی که تازه تنوع گرفته، صفر می‌شوند.
  - **شروع دفتر:** هنگام راه‌اندازی، هر کالا یا تنوعی که موجودی دارد ولی هنوز در دفتر سطری ندارد (داده‌های قبلی و کالاهای نمونه) یک سطر «موجودی اول» در انبار پیش‌فرض می‌گیرد. این کار فقط یک بار برای هر کالا انجام می‌شود.
  - **صفحهٔ «موجودی»:**
    - جدول موجودی هر کالا و هر تنوع در هر انبار، با جستجو و فیلتر «فقط ناموجودها».
    - فرم ثبت ورود، خروج، تعدیل (عدد منفی برای کاهش) و انتقال بین انبارها با SKU. انتقال دو سطر با یک شناسه است و یا کامل انجام می‌شود یا اصلاً.
  - **صفحهٔ «حرکات کالا»:** دفتر از جدید به قدیم، با فیلتر SKU (SKU کالای دارای تنوع همهٔ تنوع‌هایش را نشان می‌دهد)، انبار و نوع، مانده و نام کاربر. سطرهای خودکار نام منبعشان را دارند (ویرایش کالا، ویرایش تنوع‌ها، ورود گروهی، آغاز دفتر).
  - منوی پنل یک گروه تازهٔ «انبار» دارد. نقش Warehouse فقط همین گروه را می‌بیند.
  - ⚠️ «فروش» و «مرجوعی» با سفارش‌های فاز ۷ نوشته می‌شوند. فعلاً دستی ثبت نمی‌شوند.
- **۵ب ✅:** انبارگردانی (صفحهٔ «انبارگردانی»).
  - **شروع:** برای هر انبار فعال، حداکثر یک انبارگردانی باز. همهٔ کالاها و تنوع‌ها با موجودی همان لحظه فهرست می‌شوند، حتی ناموجودها. شماره‌ها پیوسته‌اند (ST-1، ST-2…).
  - **ثبت شمارش با SKU:** مناسب بارکدخوان (SKU، تعداد، Enter). حالت «افزودن به شمارش قبلی» برای شمردن تک‌تک. شمارش دوباره، عدد قبلی را عوض می‌کند. کالایی که بعد از شروع ساخته شده هم با اولین شمارش اضافه می‌شود.
  - **برگهٔ شمارش:** دانلود CSV یا Excel بدون موجودی دفتر (شمارش کور). برگهٔ پرشده (ستون‌های sku و counted) همه‌یا‌هیچ وارد می‌شود و ردیف‌های خالی نادیده گرفته می‌شوند.
  - **فروش در حین شمارش:** هر شمارش زمانش را نگه می‌دارد و با موجودی همان لحظه مقایسه می‌شود. موجودی آن لحظه از دفتر به دست می‌آید: موجودی فعلی منهای حرکت‌های بعد از آن. پس فروش یا ورود کالا در حین شمارش مغایرت حساب نمی‌شود.
  - **گزارش مغایرت:** موجودی هنگام شروع، موجودی دفتر، شمارش و مغایرت هر کالا، با فیلتر (همه، شمرده‌نشده، شمرده‌شده، دارای مغایرت) و جستجو، و جمع اضافه و کسری.
  - **ثبت نهایی:** هر مغایرت یک سطر «تعدیل» در دفتر با سند «ST-شماره» می‌شود. کالاهای شمرده‌نشده تغییر نمی‌کنند. انبارگردانی ثبت‌شده یا لغوشده دیگر تغییر نمی‌کند. لغو، موجودی را دست نمی‌زند.
  - کاربرِ شروع‌کننده و بندنده و زمان‌ها ثبت می‌شوند.
- **۵ج ✅:** تأمین‌کنندگان، رسید خرید، بهای تمام‌شده و هشدار حداقل موجودی.
  - **تأمین‌کنندگان** (صفحهٔ «تأمین‌کنندگان»): نام، رابط، تلفن، ایمیل، نشانی و توضیح. تأمین‌کننده‌ای که رسید دارد حذف نمی‌شود، فقط غیرفعال می‌شود.
  - **رسید خرید** (صفحهٔ «رسید خرید»):
    - هر رسید یک تأمین‌کننده، یک انبار، شمارهٔ فاکتور تأمین‌کننده و ردیف‌هایی با SKU، تعداد و بهای هر واحد دارد. شماره‌ها پیوسته‌اند (PR-1، PR-2…).
    - اول پیش‌نویس است و ردیف‌هایش تغییر می‌کند. هر کالا فقط یک ردیف دارد. جمع‌ها روی سرور حساب می‌شوند.
    - بها به ارز پایهٔ فروشگاه است و ارز روی رسید ثبت می‌شود.
    - **ثبت نهایی:** هر ردیف یک «ورود» در دفتر انبار با سند PR-شماره و بهای همان ردیف می‌شود؛ همه با هم یا هیچ. رسید ثبت‌شده دیگر تغییر نمی‌کند. برگشت کالا به تأمین‌کننده یک «خروج» در دفتر است.
  - **بهای تمام‌شده (میانگین موزون)** برای هر کالا یا تنوع روی همهٔ انبارها:
    - هر ورودِ دارای بها آن را به‌روز می‌کند: (موجودی قبلی × میانگین + تعداد × بها) ÷ (موجودی قبلی + تعداد)، با چهار رقم اعشار.
    - کالایی که هنوز بها ندارد یا موجودی‌اش صفر است، بهای همین خرید را می‌گیرد.
    - برای موجودیِ بدون رسید خرید (موجودی اول) بها را می‌شود دستی وارد کرد.
    - **هر سطر دفتر انبار بهای واحدش را نگه می‌دارد:** ورودِ خرید بهای خرید را، و حرکت‌های دیگر میانگین همان لحظه را. حسابداری فاز ۹ ارزش حرکت‌ها را از همین می‌خواند.
  - **حداقل موجودی** برای هر کالا یا تنوع (خالی یعنی بدون هشدار). کالایی که موجودی‌اش به حداقل یا کمتر برسد «کمتر از حداقل» نشان داده می‌شود.
  - **صفحهٔ موجودی:** ستون‌های بهای میانگین و ارزش (موجودی × میانگین، روی سرور)، نشان «کمتر از حداقل»، فیلتر «فقط کمتر از حداقل»، پیام تعداد کالاهای کمتر از حداقل، و فرم حداقل موجودی و بها.
  - ⚠️ هشدار ایمیلی یا پیامکی حداقل موجودی و «موجود شد» برای مشتری در فاز ۱۰ می‌آیند.
- **۵د ✅:** رزرو موجودی و جلوگیری از فروش بیش از موجودی.
  - **موجودی قابل فروش** = موجودی همهٔ انبارها − کالای رزروشده.
    - کالا و تنوع شمارندهٔ «رزرو» دارند که برابر جمع رزروهای فعال است.
    - ویترین کالا را فقط وقتی «موجود» نشان می‌دهد که موجودیِ رزرونشده مانده باشد. JSON-LD هم همین را می‌گوید.
  - **رزرو** (`StockReservationService`):
    - کالاهای یک تسویه با یک مرجع («order:1042») همه با هم رزرو می‌شوند یا هیچ‌کدام.
    - هر کالا با یک UPDATE اتمی رزرو می‌شود: «رزرو + n به شرط موجودی − رزرو ≥ n». پس دو مشتری هم‌زمان آخرین کالا را با هم نمی‌گیرند. تست روی PostgreSQL: از ده درخواست هم‌زمان فقط یکی موفق می‌شود.
  - **پایان رزرو:**
    - **ثبت فروش (پرداخت):** کالا با سطرهای «فروش» در دفتر انبار از موجودی کم می‌شود، از انبار پیش‌فرض و بعد بقیه.
    - **آزاد کردن:** خرید رها شد یا پرداخت ناموفق بود.
    - **انقضا:** پس از `Inventory:ReservationMinutes` (پیش‌فرض ۱۵ دقیقه)، یک کار پس‌زمینه هر دقیقه رزروهای تمام‌شده را آزاد می‌کند.
    - هر رزرو فقط یک بار بسته می‌شود، حتی اگر کار انقضا و آزادسازی دستی هم‌زمان برسند. رزروِ منقضی‌شده به فروش تبدیل نمی‌شود.
  - **صفحهٔ «رزروها»:** فهرست رزروهای فعال با کالا، تعداد، مرجع و زمان انقضا، و آزادسازی دستی رزروِ گیرکرده. صفحهٔ موجودی، رزرو و قابل‌فروش هر کالا را هم نشان می‌دهد.
  - ⚠️ سبد خرید و سفارش فاز ۷ همین سرویس را صدا می‌زنند: رزرو هنگام شروع پرداخت، ثبت فروش پس از تأیید پرداخت، و آزادسازی هنگام انصراف یا شکست.

## فاز ۶ — ویترین فروشگاه ✅

- صفحهٔ اصلی: **پرفروش‌ترین‌ها**، **تخفیف‌های ویژه** با شمارش معکوس، جدیدترین‌ها.
- **فیلتر** (دسته، برند، قیمت، ویژگی، موجود، تخفیف‌دار) و **مرتب‌سازی** (مرتبط‌ترین، قیمت، تاریخ عرضه، پرفروش، محبوب/امتیاز، پربازدید، بیشترین تخفیف).
- **فیلترهای پویا (facet):** گزینه‌ها از ویژگی‌های قابل فیلتر همان دسته یا همان نتیجهٔ جستجو ساخته می‌شوند، با تعداد نتیجه کنار هر گزینه (مثل «سامسونگ (۱۲)»). گزینه‌های بی‌نتیجه غیرفعال می‌شوند. بازهٔ عددی (قیمت به ارز نمایش‌داده‌شده، حافظه، اندازه) با کمینه/بیشینهٔ واقعی. فیلترهای انتخاب‌شده به‌صورت برچسب قابل حذف نمایش داده می‌شوند. همه چیز بدون JavaScript هم کار می‌کند (فرم GET).
- **جستجوی پیشرفته:**
  - Full-Text در PostgreSQL: پیکربندی `simple`، به‌علاوهٔ `pg_trgm` برای تحمل غلط تایپی (PostgreSQL برای فارسی، عربی و ارمنی ریشه‌یاب ندارد).
  - یکسان‌سازی پیش از ایندکس و پرس‌وجو: «ي/ی» و «ك/ک»، ارقام فارسی و عربی، نیم‌فاصله، اعراب، حروف کوچک لاتین.
  - **رتبه‌بندی وزن‌دار:** تطابق در نام مهم‌تر از برند و دسته، و آن‌ها مهم‌تر از توضیحات. کالای موجود و پرفروش کمی بالاتر می‌آید.
  - **چندزبانه:** جستجو در ترجمهٔ زبان فعلی، با بازگشت به زبان پیش‌فرض. نام‌های لاتین (مثل «Galaxy») در همهٔ زبان‌ها پیدا می‌شوند.
  - **کد کالا:** تطابق دقیق SKU، GTIN/بارکد و شمارهٔ عمومی محصول، که مستقیم به صفحهٔ محصول می‌رود.
  - **مترادف‌ها** از پنل.
  - **صفحه‌کلید اشتباه:** «lfhdg» به‌صورت «مبایل» هم جستجو می‌شود و برعکس (نگاشت صفحه‌کلید فارسی/انگلیسی، و برای ارمنی/انگلیسی).
  - جستجو با فیلترها و مرتب‌سازی ترکیب می‌شود.
- **پیشنهاد هنگام تایپ:** محصولات با تصویر و قیمت، دسته‌ها و برندهای مرتبط، جستجوهای پرتکرار. پاسخ سریع (هدف زیر ۱۰۰ میلی‌ثانیه سمت سرور)، با debounce و لغو درخواست قبلی.
- **نتیجهٔ صفر:** پیشنهاد «منظورتان … بود؟» (نزدیک‌ترین عبارت با `pg_trgm`)، حذف خودکار سخت‌گیرانه‌ترین فیلتر، و نمایش پرفروش‌ها به‌جای صفحهٔ خالی. عبارت‌های بی‌نتیجه برای گزارش ثبت می‌شوند.
- **موتور جستجوی قابل تعویض:** همهٔ منطق پشت `IProductSearch` است و ویترین فقط با همین رابط کار می‌کند. انتخاب با تنظیم `Search:Provider`:
  - `Postgres` (**پیش‌فرض**): بدون سرویس اضافه، کافی برای فروشگاه کوچک (تا چند هزار محصول).
  - `OpenSearch` (گزینهٔ اصلی برای فروشگاه بزرگ): مجوز Apache 2.0، تحلیلگرهای آمادهٔ `persian`، `arabic` و `armenian`، aggregation برای facet، مترادف و تحمل غلط تایپی در خود موتور.
  - `Elasticsearch`: پیاده‌سازی جداگانه (کتابخانهٔ .NET آن از نسخهٔ ۸ با OpenSearch فرق دارد)، برای فروشگاهی که خودش Elasticsearch دارد یا آن را می‌خواهد. مسئولیت مجوز (Elastic License / SSPL / AGPL) با مدیر سیستم همان نصب است.
  - Meilisearch در نسخهٔ ۱ نیست؛ اگر لازم شد، بعداً پیاده‌سازی دیگری از همین رابط است.
  - **منبع حقیقت همیشه PostgreSQL است** و موتور جستجو فقط کپی قابل بازسازی نگه می‌دارد:
    - ایندکس‌کردن قابل اطمینان با **الگوی Outbox**: تغییر محصول، قیمت، موجودی، ترجمه یا مترادف در همان تراکنش یک رکورد outbox می‌نویسد و یک سرویس پس‌زمینه آن را با تلاش دوباره به موتور می‌فرستد.
    - دستور **بازسازی کامل ایندکس** (پنل مدیر سیستم و خط فرمان)، با ایندکس جدید و جابه‌جایی alias، بدون قطعی.
    - یک ایندکس برای هر زبان فعال، با تحلیلگر همان زبان.
    - **بررسی سلامت**: اگر موتور در دسترس نباشد یا ایندکس عقب باشد، جستجو خودکار به PostgreSQL برمی‌گردد و هشدار ثبت می‌شود؛ سایت نمی‌خوابد.
    - قیمت و موجودی نمایش‌داده‌شده همیشه از PostgreSQL خوانده می‌شود، نه از ایندکس.
  - تست‌ها: یک مجموعه تست قراردادی مشترک (همان سناریوها برای هر سه موتور)؛ تست یکپارچهٔ OpenSearch/Elasticsearch با Testcontainers در CI.
  - استقرار: پروفایل اختیاری `search` در `docker-compose` که OpenSearch را فقط برای نصب‌هایی که می‌خواهند بالا می‌آورد (حداقل حدود ۲ گیگابایت RAM اضافه). در ایران، image موتور هم باید از رجیستری قابل دسترس از ایران بیاید (Elastic دانلود از ایران را مسدود می‌کند).
- **مقایسهٔ محصولات:**
  - افزودن از کارت محصول و صفحهٔ محصول، تا ۴ محصول (۲ تا روی موبایل کنار هم، بقیه با اسکرول افقی).
  - فقط محصولات **یک دسته** (یا دسته‌های با قالب ویژگی سازگار) مقایسه می‌شوند؛ افزودن از دستهٔ دیگر هشدار می‌دهد.
  - نوار شناور «مقایسه (۳)» در پایین صفحه. فهرست برای مهمان در مرورگر و برای کاربر واردشده در حساب ذخیره می‌شود و پس از ورود ادغام می‌شود.
  - جدول مقایسه: تصویر، نام، قیمت و موجودی فعلی (از سرور، نه از کش مرورگر)، امتیاز، سپس ویژگی‌های «قابل مقایسه» به ترتیب گروه‌های قالب، با واحد و ترجمه.
  - گزینهٔ **«فقط تفاوت‌ها»**، و برجسته کردن بهترین مقدار در ویژگی‌های عددی که جهت بهتر دارند (مثلاً حافظهٔ بیشتر، وزن کمتر؛ جهت در قالب ویژگی تعریف می‌شود).
  - دکمهٔ افزودن به سبد از همان جدول؛ آدرس قابل اشتراک (`/{locale}/compare?ids=…`).
  - مقادیر ترجمه‌نشده به زبان پیش‌فرض برمی‌گردند؛ مقدار خالی با «—» نمایش داده می‌شود.
- صفحهٔ محصول با گالری تصویر/ویدئو؛ **نظرات** (امتیاز، خریدار تأییدشده، تأیید ادمین، ضد اسپم)؛ علاقه‌مندی.
- SEO ویترین ([SEO-MARKETING](SEO-MARKETING.md) بندهای ۵، ۷، ۸): JSON-LD محصول/دسته/بردکرامب، canonical و `noindex` برای فیلترها، **صفحات فرود** برای ترکیب‌های پرجستجو، صفحه‌بندی با لینک واقعی، رفتار درست ناموجود/حذف‌شده، تصویر اشتراک‌گذاری خودکار، Sitemap تصویر و ویدئو.
- **بلاگ و صفحات محتوایی چندزبانه** (بند ۹).

**زیرمرحله‌ها**

- **۶الف ✅:** صفحه‌های دسته، زیردسته و برند و نتیجهٔ جستجو، با فیلتر، شمارش گزینه‌ها و مرتب‌سازی.
  - **آدرس‌ها:** `/{locale}/c/{دسته}`، `/{locale}/c/{دسته}/{زیردسته}` و `/{locale}/b/{برند}`، با slug هر زبان. «گروه کالا» در آدرس نیست و یکی از فیلترهاست.
    - کاشی‌های دسته در صفحهٔ اول حالا به صفحهٔ دسته می‌روند.
  - **API** (`GET /api/v1/catalog/browse`، `IProductBrowse`):
    - فیلترها: برند، نوع کالا، بازهٔ قیمت، فقط موجود (موجودیِ منهای رزرو)، فقط تخفیف‌دار، گزینه‌های ویژگی‌های قابل فیلتر (گزینه‌های تنوع هم حساب می‌شوند)، بازهٔ عددی، و بله/خیر.
    - مرتب‌سازی: جدیدترین، ارزان‌ترین، گران‌ترین، بیشترین تخفیف، و مرتبط‌ترین (برای جستجو). ۲۴ کالا در هر صفحه.
  - **شمارش هر گزینه** با بقیهٔ فیلترها حساب می‌شود، نه با فیلتر خودش. پس با انتخاب یک برند، شمارش برندهای دیگر هم دیده می‌شود. گزینهٔ بی‌نتیجه دیده می‌شود ولی غیرفعال است. بازهٔ قیمت و عددها کمینه و بیشینهٔ واقعی را نشان می‌دهند.
  - **پیاده‌سازی:** کالاهای محدوده به‌صورت سطرهای کوچک خوانده و در حافظه فیلتر و شمرده می‌شوند. این برای فروشگاه تا چند هزار کالا مناسب است. در ۶ج موتور جستجو فقط تطبیق متن را بر عهده گرفت؛ facet در موتور به فاز ۱۱ رفت.
  - **جستجوی ساده تا ۶ب:** همهٔ واژه‌ها (با یکسان‌سازی ی/ک، ارقام و نیم‌فاصله) باید در نام (هر زبان)، برند، واژه‌های جستجو یا SKU باشند. تطابق در نام وزن بیشتری دارد.
  - **بدون JavaScript هم کار می‌کند:**
    - گزینه‌ها پیوند واقعی `<a>` با `rel="nofollow"` هستند و بازه‌ها فرم GET.
    - روی گوشی پنل فیلتر تاشونده است و روی دسکتاپ ستون کناری.
    - فیلترهای فعال به‌صورت برچسب قابل حذف نشان داده می‌شوند، با «حذف همهٔ فیلترها».
    - صفحه‌بندی با پیوند واقعی است.
    - قیمت وارد‌شده به ارز نمایش است و برای API به ارز پایه برمی‌گردد.
  - **SEO:**
    - صفحهٔ دسته و برند: canonical به نسخهٔ بی‌فیلتر (و از صفحهٔ ۲ به خود آن صفحه)، hreflang فقط برای زبان‌های ترجمه‌شده، و `BreadcrumbList` + `ItemList` در JSON-LD.
    - فیلتر یا مرتب‌سازی، و زبانِ ترجمه‌نشده: `noindex,follow`. جستجو همیشه `noindex`.
  - ⚠️ «بیشترین امتیاز» در ۶ه اضافه شد؛ «پرفروش‌ترین» بعد از سفارش‌ها (فاز ۷) می‌آید.
- **۶ب ✅:** جستجوی پیشرفته.
  - **سند جستجو:** برای هر کالای منتشرشده در هر زبان یک سند، همه با یک املا (ی/ک، ارقام، نیم‌فاصله، اعراب، حروف کوچک) و در چهار وزن:
    - نام در همان زبان؛
    - نام زبان پیش‌فرض (تا نام‌های لاتین مثل «Galaxy» در همهٔ زبان‌ها پیدا شوند)، برند، و دسته/زیردسته/گروه؛
    - واژه‌های جستجو، مقدار ویژگی‌ها، گزینه‌های تنوع، و SKU و بارکد و شماره؛
    - توضیحات.
  - **Outbox:**
    - یک interceptor در EF هر تغییر کاتالوگ را در همان تراکنش در صف `search_outbox` می‌گذارد. این تغییرها شامل کالا، ترجمه، تنوع، مقدار ویژگی، و نام برند، دسته، زیردسته، گروه، ویژگی و گزینه است. پس هیچ نویسنده‌ای فراموشش نمی‌کند.
    - یک سرویس پس‌زمینه هر چند ثانیه سندهای تغییرکرده را از نو می‌سازد.
    - فروشگاهی که سند ندارد، هنگام راه‌اندازی یک ساخت کامل می‌گیرد. در پنل سئو هم دکمهٔ «بازسازی ایندکس» و وضعیت صف هست.
  - **موتور (`IProductSearch`):**
    - روی PostgreSQL، Full-Text با پیکربندی `simple` و ستون `tsvector` وزن‌دار تولیدی با ایندکس GIN. هر واژه به‌صورت پیشوندی جستجو می‌شود (sams → samsung).
    - `pg_trgm` (‏`word_similarity` روی نام) غلط تایپی را تحمل می‌کند.
    - روی پایگاه‌های دیگر و در تست‌ها، موتور سادهٔ درون‌حافظه‌ای بدون تحمل غلط کار می‌کند.
  - **کد کالا:** SKU (تنوع هم)، بارکد یا شمارهٔ عمومی مستقیم به صفحهٔ کالا می‌رود.
  - **مترادف‌های پنل:** هر واژه با هم‌گروه‌هایش جستجو می‌شود. عبارتِ چندکلمه‌ای مثل «تلفن همراه» یک واژه حساب می‌شود.
  - **صفحه‌کلید اشتباه:** «i,nd» همان «هودی» است. فارسی↔انگلیسی و ارمنی آوایی↔انگلیسی، با پیام «نتیجه‌ها برای … نشان داده شده است».
  - **نتیجهٔ صفر:**
    - «منظورتان … بود؟»: نزدیک‌ترین واژهٔ فروشگاه، با `pg_trgm` روی PostgreSQL و فاصلهٔ ویرایشی در موتور ساده.
    - پیوند «بدون فیلتر X (N کالا)» برای فیلتری که بیشترین کالا را پنهان کرده (در صفحهٔ دسته هم).
    - جدیدترین کالاها به‌جای صفحهٔ خالی.
  - **ثبت جستجوها:** شمار هر عبارت و تعداد بی‌نتیجه‌ها برای هر زبان در `search_term_stats`. گزارشش در فاز ۱۰ می‌آید.
  - **پیشنهاد هنگام تایپ** (`GET /catalog/suggest`، از دو حرف):
    - محتوا: کالا با تصویر و قیمت به ارز نمایش، دسته، برند، و جستجوهای پرتکرارِ بانتیجه.
    - رفتار: صبر ۲۰۰ میلی‌ثانیه‌ای پس از تایپ، لغو درخواست قبلی، حرکت با کلیدهای جهت، Enter برای باز کردن و Escape برای بستن.
    - بدون JavaScript همان فرم GET ساده است.
  - ⚠️ ترکیب «کالای موجود و پرفروش کمی بالاتر» فقط بخش «موجود» را دارد: پرفروش‌ها بعد از سفارش‌های فاز ۷ می‌آیند.
- **۶ج ✅:** موتور جستجوی قابل تعویض.
  - **انتخاب:** `Search:Provider` = `Postgres` (پیش‌فرض) / `OpenSearch` / `Elasticsearch`، و نشانی و اعتبار در `Search:Engine` (نام کاربری و گذرواژه، یا API key برای Elasticsearch).
  - **یک کلاینت REST:** هر دو موتور برای کارهای ما همان API را دارند. پس کتابخانهٔ .NET هیچ‌کدام لازم نیست، چون نسخه‌های آن‌ها با هم فرق دارند. این جای «دو پیاده‌سازی جدا»ی طرح اولیه را گرفت.
  - **ایندکس:**
    - برای هر زبان یک ایندکس با تحلیلگر همان زبان (`persian`، `arabic`، `armenian`، `german`، `english` و …) و mapping سخت‌گیر.
    - تطابق پیشوندی، غلط تایپی (fuzziness)، و یک فیلد «words» برای «منظورتان … بود؟».
    - نام ایندکس `{prefix}-{زبان}-{زمان}` است و جستجو از alias `{prefix}-{زبان}` انجام می‌شود. با prefix جدا، چند فروشگاه یک خوشه را با هم شریک می‌شوند.
  - **همگام‌سازی:**
    - سند جستجو در PostgreSQL منبع حقیقت می‌ماند.
    - Outbox دوم (`search_engine_outbox`) در همان تراکنشی پر می‌شود که سندها بازسازی می‌شوند.
    - نوشتن با `require_alias` انجام می‌شود، تا نوشتن روی alias ناموجود هیچ‌وقت ایندکس حدسی نسازد.
    - بازسازی کامل (دکمهٔ پنل سئو، یا موتوری که ایندکس ندارد) ایندکس‌های تازه می‌سازد و alias را یک‌جا جابه‌جا می‌کند. پس قطعی ندارد و ایندکس‌های قدیمی پاک می‌شوند.
  - **سلامت و بازگشت به پایگاه داده:**
    - جستجو فقط وقتی به موتور می‌رود که ساخته شده باشد، بیش از `MaxLagSeconds` (۵ دقیقه) عقب نباشد و تازه خطا نداده باشد.
    - در غیر این صورت، یا با خطا یا timeout (۳ ثانیه)، پایگاه داده جواب می‌دهد و یک هشدار در لاگ ثبت می‌شود.
    - موتور پس از `RetrySeconds` دوباره امتحان می‌شود.
    - پنل سئو نشان می‌دهد که موتور الان پاسخ می‌دهد یا نه، و چند کالا در صف است.
  - **تست‌ها:**
    - تست‌های واحد: بدنهٔ درخواست‌ها، کلاینت HTTP، همگام‌سازی و مسیریابی و بازگشت به پایگاه داده.
    - تست یکپارچهٔ مشترک «همان سناریو برای هر موتور». در CI روی OpenSearch و Elasticsearch به‌صورت service container اجرا می‌شود (به جای Testcontainers). روی ماشینی که موتور ندارد بی‌صدا رد می‌شود.
  - **استقرار:** پروفایل `search` در `docker-compose` با OpenSearch، با متغیرهای `SEARCH_*` و `SEARCH_IMAGE` برای رجیستری قابل دسترس از ایران.
  - ⚠️ فیلترها و شمارش گزینه‌ها هنوز در حافظه روی سطرهای PostgreSQL حساب می‌شوند و موتور فقط متن را تطبیق می‌دهد. انتقال facetها به aggregation موتور برای کاتالوگ خیلی بزرگ به فاز ۱۱ (کارایی) منتقل شد.
  - ⚠️ بازسازی از خط فرمان نیست؛ از پنل سئو یا با پاک کردن ایندکس انجام می‌شود (ایندکس گم‌شده خودکار از نو ساخته می‌شود).
- **۶د ✅:** مقایسهٔ کالاها.
  - **افزودن:** دکمهٔ «مقایسه» گوشهٔ کارت کالا و در جعبهٔ قیمت صفحهٔ کالا.
    - روشن و خاموش می‌شود (`aria-pressed`). بدون JavaScript پیوندی است به صفحهٔ مقایسه با همان کالا.
    - حداکثر ۴ کالا. کالای دستهٔ دیگر یا کالای پنجم پیام می‌دهد: «شروع مقایسهٔ تازه» یا «انصراف».
  - **نوار شناور «مقایسه (۳)»:** روی گوشی بالای نوار پایین، با دکمهٔ پاک کردن فهرست. در صفحهٔ مقایسه و پنل مدیریت دیده نمی‌شود.
  - **ذخیره:**
    - مهمان: در `localStorage` مرورگر.
    - کاربر واردشده: در حساب (`compare_items`، `GET`/`PUT /api/v1/account/compare`). پس از ورود، فهرست مهمان در آن ادغام می‌شود. فهرست ذخیره‌شده پس از خروج از مرورگر پاک می‌شود.
    - حساب فقط وقتی پرسیده می‌شود که فهرستی هست، نه در هر بازدید. برای مهمان پاسخ ۲۰۰ با `signedIn: false` است، نه ۴۰۱.
    - این فهرست دادهٔ شخصی است: در خروجی دادهٔ شخصی هست و با حذف حساب پاک می‌شود.
  - **صفحهٔ `/{locale}/compare?ids=…`:**
    - آدرس قابل اشتراک. بدون `ids`، فهرست ذخیره‌شدهٔ کاربر نشان داده می‌شود.
    - `noindex,follow` است و در robots.txt هم بسته است.
    - قیمت و موجودی هر بار از سرور خوانده می‌شود (بدون کش).
  - **جدول:**
    - تصویر، نام، برند، قیمت، موجودی، سپس ویژگی‌های «قابل مقایسه» به ترتیب گروه‌ها.
    - گزینه‌های تنوع هم می‌آیند (مثلاً رنگ‌های موجود). مقدار ترجمه‌نشده به زبان پیش‌فرض برمی‌گردد و مقدار خالی «—» است.
    - نام هر ویژگی یک ردیف تمام‌عرض بالای مقدارهاست. پس روی گوشی دو کالا کنار هم جا می‌شوند و بقیه با اسکرول افقی دیده می‌شوند. سلول‌ها با `headers` به سرستون‌ها وصل‌اند.
  - **«فقط تفاوت‌ها»:** پیوند `?diff=1`، بدون JavaScript هم کار می‌کند.
  - **بهترین مقدار:** ویژگی عددی «جهت بهتر» دارد (`SpecBetter`: هیچ‌کدام، بیشتر یا کمتر، در ویرایشگر ویژگی پنل). بهترین مقدار وقتی مقدارها فرق دارند برجسته می‌شود.
  - **قاعدهٔ «یک دسته»:** هنگام افزودن، دستهٔ اصلی کالا بررسی می‌شود. اگر کالاهای جدول از چند دسته باشند (مثلاً آدرس اشتراکی)، پیام «ویژگی‌ها مشترک نیستند» نشان داده می‌شود. «دسته‌های با قالب سازگار» هنوز نیست.
  - ⚠️ ردیف امتیاز در ۶ه اضافه شد. «افزودن به سبد» از جدول هنوز نیست (۷الف فقط صفحهٔ کالا را پوشش داد). فعلاً دکمهٔ «مشاهدهٔ کالا» هست.
- **۶ه ✅:** نظرات و علاقه‌مندی.
  - **نوشتن نظر:**
    - ۱ تا ۵ ستاره، عنوان اختیاری و متن ۱۰ تا ۲۰۰۰ نویسه. برای هر مشتری و هر کالا یک نظر؛ نوشتن دوباره نظر قبلی را جایگزین می‌کند و دوباره به صف تأیید می‌رود.
    - فقط حسابی که ایمیل یا موبایلش تأیید شده نظر می‌نویسد.
    - «خریدار این کالا» از سفارش‌های پرداخت‌شده تعیین می‌شود.
  - **ضد اسپم:** ورود لازم است، پیوند (http، www، دامنه) رد می‌شود، حداکثر ۵ نظر در ساعت برای هر مشتری، و محدودیت درخواست `reviews` برای هر IP.
  - **تأیید مدیر:**
    - صفحهٔ `/admin/reviews` با مجوز `reviews.moderate`: فیلتر وضعیت، تأیید و رد، و شمار نظرهای منتظر.
    - فقط نظر تأییدشده نشان داده می‌شود و در امتیاز حساب می‌شود.
    - امتیاز کالا (`RatingAverage`، `RatingCount`) با هر تغییر دوباره حساب می‌شود.
    - تأیید، کش `reviews` ویترین را پاک می‌کند.
  - **نمایش:**
    - امتیاز کنار عنوان صفحهٔ کالا و روی کارت کالا و جدول مقایسه.
    - بخش «نظرات کاربران» در HTML اولیه: میانگین، شمار هر ستاره، نظرها از جدید به قدیم، و صفحه‌بندی با `?reviews=N` (canonical همان صفحهٔ کالاست).
    - هر نظر با زبان خودش (`lang`) نشان داده می‌شود.
    - JSON-LD شامل `AggregateRating` و `Review` است، فقط برای همان نظرهای تأییدشده‌ای که در صفحه دیده می‌شوند.
    - مرتب‌سازی «بیشترین امتیاز» (`sort=rating`) در فهرست‌ها.
  - **فرم نظر:**
    - فقط وقتی باز می‌شود از API می‌پرسد، پس صفحهٔ کالا درخواست اضافه ندارد. مهمان به صفحهٔ ورود می‌رود و با `#reviews` برمی‌گردد.
    - وضعیت نظر خود کاربر (در انتظار، منتشرشده، ردشده) را نشان می‌دهد و حذف آن ممکن است.
  - **علاقه‌مندی:**
    - دکمهٔ قلب در صفحهٔ کالا، فقط برای کاربر واردشده (مهمان به صفحهٔ ورود می‌رود؛ بدون JavaScript پیوند است).
    - صفحهٔ `/account/wishlist` با کارت‌ها و قیمت و موجودی فعلی، از جدید به قدیم.
    - پرسش `GET /account/wishlist/ids` برای مهمان ۲۰۰ با `signedIn: false` برمی‌گرداند.
  - **دادهٔ شخصی:** نظرها و علاقه‌مندی‌ها در خروجی دادهٔ شخصی هستند و با حذف حساب پاک می‌شوند؛ امتیاز کالاها هم دوباره حساب می‌شود.
  - ⚠️ اعلان «موجود شد» و «کاهش قیمت» برای علاقه‌مندی‌ها ([SEO-MARKETING](SEO-MARKETING.md) بند ۱۲) به فاز ۱۰ (پنل و گزارش‌ها) و ایمیل‌های بازاریابی موکول شد.
  - ⚠️ پاسخ فروشگاه به نظر، «مفید بود؟» و عکس در نظر هنوز نیست. دکمهٔ قلب روی کارت‌ها هم نیست (تا صفحه‌های فهرست درخواست اضافه نداشته باشند).
- **۶و ✅:** SEO ویترین.
  - **Sitemap:**
    - `/sitemap.xml` فهرست (sitemap index) است و پنج بخش دارد: `/sitemaps/sitemap/{pages,products,categories,brands,landing}.xml`.
    - هر صفحه فقط در زبان‌هایی که ترجمه شده می‌آید، با `hreflang` و `x-default` و `lastmod` واقعی.
    - کالاها با افزونهٔ تصویر و ویدئو می‌آیند (ویدئوی بی‌پوستر از افزونهٔ ویدئو کنار می‌ماند).
    - دسته و زیردسته و برند فقط وقتی کالای منتشرشده دارند فهرست می‌شوند.
    - داده از `GET /api/v1/catalog/sitemap/{kind}` می‌آید (`SitemapService`). سقف هر بخش ۱۰٬۰۰۰ صفحه است و تقسیم بیشتر لازم نشد.
  - **صفحات فرود** (`/{locale}/l/{slug}`):
    - برای ترکیب‌های پرجستجو (مثلاً یک برند در یک دسته): عنوان، نشانی و متن برای هر زبان، عنوان و توضیح جستجو، و یک پرس‌وجوی ثابت فهرست.
    - مدیر نشانی یک فهرست فیلترشده را می‌چسباند و `LandingQuery.Normalize` آن را به پرس‌وجو تبدیل می‌کند؛ پرس‌وجو با اجرای browse بررسی می‌شود.
    - ایندکس می‌شوند، برخلاف فهرست‌های فیلترشده: canonical به خودش (`?page=N` از صفحهٔ ۲) و hreflang فقط برای زبان‌های ترجمه‌شده.
    - مرتب‌سازی دیگر `noindex,follow` است و زبان ترجمه‌نشده canonical به زبان پیش‌فرض دارد.
    - JSON-LD شامل `BreadcrumbList` و `ItemList` است.
    - بازدیدکننده فقط مرتب‌سازی و صفحه را عوض می‌کند و فیلترها بخشی از صفحه‌اند (پنل فیلتر ندارد).
    - پنل: `/admin/landing` با مجوز `content.manage`.
  - **تخفیف ویژه با شمارش معکوس:**
    - `Product.SaleEndsUtc` («پایان پیشنهاد» در ویرایشگر کالا) فقط همراه قیمت قبلی معتبر است.
    - `SaleExpiryService` هر دقیقه پیشنهادهای تمام‌شده را می‌بندد: قیمت قبلی دوباره قیمت می‌شود، برای تنوع‌های با قیمت قبلی خودشان هم.
    - فهرست `SpecialOffers` (زودترین پایان اول) در نوار پیشنهادهای صفحهٔ اول، به جای «تخفیف‌دارها» وقتی پیشنهادی در جریان است.
    - شمارش معکوس روی کارت و صفحهٔ کالا. سرور فقط برچسب را می‌فرستد و ساعت در مرورگر می‌شمارد، تا اختلاف ساعت پیش نیاید.
    - JSON-LD شامل `priceValidUntil` است.
    - کش کالا و فهرست‌ها در وب پیش از پایان پیشنهاد منقضی می‌شود (`saleAwareLife`)، پس قیمت پیشنهادی بعد از پایان نمایش داده نمی‌شود.
  - ⚠️ تصویر اشتراک‌گذاری خودکار (`next/og`) و صفحات فرود با متن بالای فهرست دسته/برند (بند ۹) هنوز نیستند. متن توضیحی دسته از ۶الف هست.
- **۶ز ✅:** بلاگ و صفحات محتوایی چندزبانه.
  - **نوع‌ها:**
    - **نوشتهٔ وبلاگ** در `/{locale}/blog/{slug}`.
    - **صفحه** (مثل «دربارهٔ ما») در `/{locale}/{slug}`. نشانی‌های خود فروشگاه مثل `account`، `blog`، `c`، `p`، `search` و `compare` برای صفحه رزرو شده‌اند.
  - **محتوا:**
    - عنوان، نشانی، خلاصه، متن، عنوان و توضیح جستجو، و برچسب‌ها برای هر زبان، که دستی نوشته می‌شوند.
    - زبان خالی متن زبان اصلی را نشان می‌دهد و `noindex` است، با canonical به زبان اصلی.
    - نشانی در هر نوع و هر زبان یکتاست.
  - **متن با چند نشانهٔ ساده:**
    - نشانه‌ها: خط خالی برای بند، `##` و `###` برای عنوان، `-` و `1.` برای فهرست، `>` برای نقل‌قول، `**پررنگ**`، و `[پیوند](...)`.
    - پیوند فقط به نشانی‌های خود سایت، `#`، `http(s)` یا `mailto` مجاز است.
    - هیچ HTMLی از متن به صفحه نمی‌رسد (`lib/content/markdown.tsx`).
  - **نوشته‌ها:**
    - نویسنده، تصویر شاخص (مثل بقیهٔ تصویرها به WebP تبدیل می‌شود)، و زمان انتشار. زمان آینده یعنی زمان‌بندی؛ نوشته تا آن زمان نشان داده نمی‌شود.
    - تا ۱۲ کالای مرتبط با شماره که زیر نوشته نشان داده می‌شوند.
    - صفحه‌های وبلاگ از جدید به قدیم، با فهرست برچسب‌ها (`?tag=`، `noindex`) و صفحه‌بندی واقعی.
    - برچسب‌ها با ویرگول فارسی «،» هم جدا می‌شوند.
  - **صفحه‌ها:** با گزینهٔ «پیوند در پایین سایت» در ستون تازهٔ «دربارهٔ فروشگاه» پیوند می‌گیرند. پیوند وبلاگ هم همان‌جاست.
  - **SEO:**
    - JSON-LD برای نوشته `BlogPosting` (عنوان، نویسنده، تاریخ‌ها، تصویر، زبان، برچسب‌ها) و برای صفحه `WebPage`، هر دو با `BreadcrumbList`.
    - hreflang فقط برای زبان‌های ترجمه‌شده است.
    - Open Graph برای نوشته‌ها از نوع `article` است.
    - Sitemap دو بخش تازه دارد (`posts` و `content`)، و `/blog` در بخش صفحه‌ها آمده است.
  - **پنل:** «وبلاگ و صفحه‌ها» (`/admin/content`، با مجوز `content.manage`). ذخیره، کش `content` ویترین را پاک می‌کند.
  - ⚠️ نشانی ناشناختهٔ یک‌بخشی (مثل `/fa/xyz`) حالا مثل محصول ناموجود «404 نرم» است: پاسخ ۲۰۰ همراه `noindex` و متن «پیدا نشد»، چون صفحه استریم می‌شود. تبدیل آن به 404 واقعی در `proxy.ts`، مثل slug محصول، به فاز ۱۱ رفت.
  - ⚠️ دسته‌بندی جدا برای نوشته‌ها (به جز برچسب)، نظر زیر نوشته، فید RSS و ویرایشگر دیداری متن در نسخهٔ ۱ نیست.

## فاز ۷ — سبد خرید، تسویه و سفارش 🔄

- **کلیات:**
  - سبد مهمان و ادغام پس از ورود؛ قیمت فقط سمت سرور؛ آدرس، کد تخفیف.
  - **مالیات ساده:** یک نرخ برای فروشگاه، قیمت با/بدون مالیات؛ **فاکتور PDF** چندزبانه با شمارهٔ پیوسته.
  - **ارسال:** روش‌های قابل تعریف از پنل (هزینهٔ ثابت، بر اساس وزن/منطقه، رایگان بالای مبلغ مشخص، تحویل حضوری)؛ ثبت دستی کد رهگیری. اتصال API شرکت‌های حمل در نسخهٔ ۱ نیست.
  - **مرجوعی و بازپرداخت:** درخواست مشتری، تأیید ادمین، برگشت کالا به انبار، بازپرداخت از درگاه یا دستی؛ مهلت انصراف قابل تنظیم (۱۴ روز برای اروپا).
  - چرخهٔ عمر سفارش با تاریخچه؛ چک مالکیت در همهٔ عملیات؛ ایمیل چندزبانه (و پیامک در صورت فعال بودن)؛ اعلان PWA (Web Push) اختیاری.
- **گام‌ها:**
  - **۷الف ✅** سبد خرید.
  - **۷ب ✅** تسویه: آدرس (از دفترچه یا برای مهمان)، روش‌های ارسال از پنل، مالیات یک‌نرخی، کد تخفیف، و ساخت سفارش با رزرو موجودی از `StockReservationService`.
  - **۷ج ⬜** چرخهٔ عمر سفارش: وضعیت‌ها با تاریخچه، صفحهٔ «سفارش‌های من»، فهرست و جزئیات سفارش در پنل، کد رهگیری، ایمیل و پیامک.
  - **۷د ⬜** فاکتور PDF با شمارهٔ پیوسته، مرجوعی و بازپرداخت.
  - **۷هـ ⬜** اعلان Web Push اختیاری.
- **۷الف ✅:** سبد خرید.
  - **سبد سمت سرور، برای مهمان هم:**
    - مهمان با اولین «افزودن» یک توکن تصادفی ۲۵۶ بیتی در کوکی HttpOnly `os_cart` می‌گیرد (۶۰ روز). در پایگاه داده فقط هش SHA-256 آن ذخیره می‌شود.
    - مشتری واردشده سبد خودش را دارد (`carts.customer_id`) و روی همهٔ دستگاه‌هایش همان را می‌بیند.
  - **ادغام پس از ورود:** اولین درخواست سبد پس از ورود، سبد مهمان را به حساب می‌برد و کوکی آن را پاک می‌کند.
    - اگر حساب سبدی نداشت، سبد مهمان همان سبد حساب می‌شود.
    - وگرنه تعدادها جمع می‌شوند (حداکثر به اندازهٔ موجودی) و سبد مهمان حذف می‌شود.
  - **ردیف‌ها:** هر ردیف یک کالا یا یک تنوع است (`item_id` = شناسهٔ تنوع، وگرنه شناسهٔ کالا؛ یکتا در هر سبد). کالای دارای تنوع بدون انتخاب تنوع پذیرفته نمی‌شود.
  - **قیمت و موجودی همیشه زنده:**
    - سبد فقط کالا و تعداد را نگه می‌دارد. قیمت (قیمت تنوع یا کالا)، قیمت قبلی و موجودی (Stock − Reserved) در هر پاسخ از پایگاه داده خوانده می‌شود.
    - افزودن یا بیشتر کردن تعداد بیش از موجودی رد می‌شود (`cart.not_enough_stock`). کم کردن همیشه مجاز است.
    - ردیفی که بعداً تغییر کرده علامت می‌خورد (ناموجود، موجودی ناکافی، دیگر عرضه نمی‌شود) و در جمع حساب نمی‌شود.
    - سقف ۹۹ عدد در هر ردیف و ۵۰ ردیف در سبد.
  - **API:** `GET /api/v1/cart`، `POST /cart/items` (شمارهٔ کالا و SKU تنوع)، `PUT` و `DELETE /cart/items/{id}`. ردیف سبد دیگران پیدا نمی‌شود (404).
  - **نشان تعداد:** کوکی خواندنی `os_cart_n` تعداد کالاها را دارد. نشان روی آیکن سبد در سربرگ و نوار پایین موبایل بدون هیچ درخواستی از آن خوانده می‌شود، پس صفحه‌ها برای همه یکسان و قابل کش می‌مانند.
  - **وب:**
    - دکمهٔ «افزودن به سبد» در صفحهٔ کالا فعال شد. برای کالای دارای تنوع، دکمه در انتخابگر تنوع است و تنوع انتخاب‌شده را می‌فرستد.
    - پس از افزودن، پیام «به سبد خرید اضافه شد» و پیوند «دیدن سبد خرید» نشان داده می‌شود، و خطاها با متن ترجمه‌شده.
    - صفحهٔ `/{locale}/cart` (noindex) شامل این‌هاست: تصویر، نام با پیوند، تنوع، قیمت (با قیمت قبلی و «هر عدد»)، دکمه‌های − و + و حذف، هشدار ردیف‌های تغییرکرده، و جمع.
    - قیمت به ارز نمایشی تبدیل می‌شود: قیمت واحد تبدیل و سپس در تعداد ضرب می‌شود، تا ردیف‌ها و جمع با هم بخوانند.
    - دکمهٔ «ادامهٔ فرایند خرید» تا ۷ب غیرفعال است.
  - کدهای خطای `cart.*` در `cart.errors` هر پنج زبان ترجمه شده‌اند.
  - ⚠️ «افزودن به سبد» بدون JavaScript کار نمی‌کند (بقیهٔ صفحهٔ کالا کار می‌کند). افزودن از جدول مقایسه هم هنوز نیست.
  - ⚠️ سبدهای مهمانِ رهاشده هنوز پاک نمی‌شوند. پاک‌سازی دوره‌ای (مثلاً بعد از ۶۰ روز بی‌تغییری) به ۷ج رفت.
  - ⚠️ صفحهٔ سبدی که سرور می‌سازد کوکی را عوض نمی‌کند. پس پس از ادغام، خود صفحه نشان تعداد را با `CartCountSync` به‌روز می‌کند.
- **۷ب ✅:** تسویه و ثبت سفارش.
  - **صفحهٔ تسویه** (`/{locale}/checkout`، noindex):
    - بخش‌ها: تماس، روش ارسال، نشانی (یا تحویل‌گیرنده برای تحویل حضوری)، یادداشت، و خلاصه با کد تخفیف.
    - مشتری واردشده از دفترچهٔ نشانی انتخاب می‌کند یا نشانی تازه می‌دهد (و می‌تواند آن را ذخیره کند). مهمان نشانی را وارد می‌کند.
    - مهمان وقتی پیامک خاموش است باید ایمیل بدهد. با `Store:GuestCheckout=false` به صفحهٔ ورود فرستاده می‌شود.
    - دکمهٔ «ادامهٔ فرایند خرید» در سبد فعال شد. وقتی ردیفی مشکل دارد، غیرفعال است تا سبد اصلاح شود.
  - **محاسبه فقط سمت سرور:**
    - با هر تغییر کشور، روش ارسال یا کد تخفیف، `POST /checkout/quote` جمع‌ها را از سبد زنده حساب می‌کند. کد نامعتبر خطای کل پیش‌فاکتور نیست و فقط کنار کد نشان داده می‌شود.
    - ثبت سفارش مبلغی را که مشتری دیده (`ExpectedTotal`) می‌فرستد. اگر قیمت در این فاصله عوض شده باشد، سفارش با `checkout.total_changed` رد می‌شود و جمع تازه نمایش داده می‌شود؛ مبلغ متفاوت هرگز گرفته نمی‌شود.
    - مبالغ به ارز پایه، یعنی ارز سفارش، نمایش داده می‌شوند و هر مبلغ با رقم اعشار همان ارز گرد می‌شود (ریال بدون اعشار).
  - **روش‌های ارسال** (`ShippingMethod`، پنل «ارسال و مالیات» با مجوز `settings.manage`):
    - نام و توضیح برای هر زبان.
    - هزینهٔ ثابت به‌علاوهٔ هزینه برای هر کیلوگرمِ شروع‌شده (از `WeightGrams` کالا).
    - رایگان از یک مبلغ، که بعد از تخفیف سنجیده می‌شود.
    - کشورهای مشخص (منطقه)؛ خالی یعنی همهٔ کشورهای ارسال.
    - تحویل حضوری بدون نشانی، با نام و موبایل تحویل‌گیرنده.
    - زمان تحویل (از/تا روز)، ترتیب، و فعال یا غیرفعال.
  - **مالیات** (`TaxSettings`، همان صفحه): یک نرخ برای فروشگاه، و انتخاب «قیمت‌ها و هزینهٔ ارسال شامل مالیات‌اند» یا «مالیات اضافه می‌شود».
    - مالیات روی کالا پس از تخفیف به‌علاوهٔ هزینهٔ ارسال، با همان نرخ، محاسبه می‌شود.
    - سفارش نرخ و نوع مالیات را با خودش نگه می‌دارد.
  - **کدهای تخفیف** (`DiscountCode`، پنل «کدهای تخفیف» با مجوز `discounts.manage`):
    - انواع: درصد (با سقف)، مبلغ ثابت، و ارسال رایگان.
    - شرط‌ها: حداقل مبلغ سفارش، بازهٔ تاریخ (به UTC)، سقف کل استفاده، و «یک بار برای هر مشتری» (حساب، ایمیل یا شمارهٔ تلفن سفارش‌های لغونشده).
    - شمارش استفاده با یک UPDATE شرطی انجام می‌شود، پس آخرین استفاده را فقط یک سفارش می‌گیرد.
    - کد ناشناخته، غیرفعال، شروع‌نشده و تمام‌شده همه یک پاسخ دارند (`checkout.discount_invalid`).
  - **ثبت سفارش** (`POST /checkout/orders`، در یک تراکنش):
    - شمارهٔ سفارش پیوسته از ۱۰۰۱ است. اگر دو سفارش هم‌زمان یک شماره بگیرند، ایندکس یکتا یکی را رد می‌کند و آن یکی دوباره تلاش می‌کند.
    - موجودی همهٔ کالاها با مرجع `order:{شماره}` و به‌صورت «همه یا هیچ» رزرو می‌شود. `PaymentDueUtc` زمان پایان رزرو است (۱۵ دقیقه، `Inventory:ReservationMinutes`).
    - استفادهٔ کد تخفیف شمرده می‌شود.
    - همه‌چیز کپی می‌شود: کالا با SKU، برچسب تنوع، قیمت و تعداد؛ روش ارسال؛ نرخ مالیات؛ ارز و نرخ تبدیل (۱ تا فاز ۸)؛ تماس و نشانی.
    - سبد خالی و کوکی‌های آن پاک می‌شوند.
    - سفارش در وضعیت `Pending` منتظر پرداخت می‌ماند (فاز ۸).
    - محدودیت نرخ `checkout` (۱۰ در دقیقه برای هر نشانی IP) جلوی قفل کردن موجودی با اسکریپت را می‌گیرد.
  - **مالکیت:** نشانی دفترچه فقط با شناسهٔ خود مشتری در خود کوئری پیدا می‌شود (`a.Id == id && a.CustomerId == userId`).
  - **اطلاعات شخصی:** سفارش حالا ایمیل، نام، تلفن، نشانی و یادداشت دارد.
    - این‌ها در خروجی اطلاعات شخصی هستند.
    - با حذف حساب پاک می‌شوند؛ مبالغ و کشور سفارش می‌مانند.
  - کدهای خطای `checkout.*`، `shipping.*` و `discount.*` در هر پنج زبان ترجمه شده‌اند.
  - ⚠️ سفارشی که مهلت پرداختش تمام شده، پس از آزاد شدن رزرو هنوز `Pending` می‌ماند. لغو خودکار آن (و برگرداندن شمارش کد تخفیف) در ۷ج می‌آید، همراه صفحهٔ «سفارش‌های من»، سفارش‌ها در پنل و ایمیل تأیید سفارش.
  - ⚠️ صفحهٔ تأیید فقط بلافاصله پس از ثبت نشان داده می‌شود. پیگیری سفارش مهمان با پیوند ایمیل در ۷ج می‌آید.
  - ⚠️ تسویه بدون JavaScript کار نمی‌کند (صفحهٔ خصوصی است، نه صفحهٔ عمومی SEO).

## فاز ۸ — ارز و درگاه‌های پرداخت ⬜

- تنظیمات ارز و درگاه مدیر سیستم (جدول بالا).
- `IPaymentGateway` (Strategy): Stripe، PayPal، زرین‌پال، سداد، به‌پرداخت ملت.
- نرخ تبدیل ارز: جدول ارزها، نرخ دستی و خودکار و گرد کردن برای هر ارز در فاز ۳ ساخته شد (ارزهای نمایشی). مانده: ارزهای قابل پرداخت هر درگاه، و ثبت ارز و نرخ استفاده‌شده روی هر سفارش.
- تأیید فقط سمت سرور (Verify/Webhook با بررسی امضا)، Idempotency، ثبت تراکنش، بازپرداخت.

## فاز ۹ — حسابداری ⬜

- دفتر کل دوطرفه، سرفصل حساب‌ها، سند خودکار از فروش/پرداخت/بازپرداخت/خرید/تعدیل انبار؛ حسابداری چندارزی.
- هزینه‌ها، صندوق/بانک؛ گزارش سود و زیان، فروش، مالیات، ارزش موجودی؛ خروجی Excel/PDF؛ اسناد قطعی غیرقابل ویرایش.

## فاز ۱۰ — پنل مدیریت و گزارش‌ها ⬜

- داشبورد، مدیریت کاربران و نقش‌ها، تنظیمات فروشگاه/ارز/درگاه/پیامک/روش ورود/قالب، **لاگ ممیزی**.
- صفحات قانونی قابل ویرایش: قوانین، حریم خصوصی، بنر رضایت کوکی (اروپا)، Impressum (آلمان)، جای نماد اعتماد/اینماد (ایران).
- آمار فروش و بازدید داخلی و حافظ حریم خصوصی؛ GTM/GA4، Meta Pixel، Matomo اختیاری و **فقط پس از رضایت کاربر** (Consent Mode v2)؛ dataLayer استاندارد رویدادهای فروشگاهی.
- ثبت `utm_*` و ارجاع‌دهنده روی سفارش و گزارش فروش بر اساس کمپین/کانال؛ گزارش عبارات جستجو و 404ها؛ مدیریت Redirect.
- **فیدهای محصول:** Google Merchant Center، Meta Catalog، ترب، ایمالز (پشت `IProductFeed`).
- خبرنامه با Double opt-in، ایمیل «موجود شد» و «کاهش قیمت». فرم تماس و پیام روی سفارش؛ چت آنلاین در نسخهٔ ۱ نیست.

## فاز ۱۱ — کارایی، SEO و سخت‌سازی امنیتی ⬜

- کش (Output cache، ISR در Next.js)، فشرده‌سازی، کوئری‌های بهینه؛ هدف **Lighthouse ≥ 90** در موبایل.
- برای کاتالوگ خیلی بزرگ با موتور جستجو: facet و فیلترها با aggregation همان موتور (مانده از ۶ج). قیمت و موجودی نمایش‌داده‌شده همچنان از PostgreSQL خوانده می‌شود.
- ممیزی کامل با [چک‌لیست پذیرش SEO](SEO-MARKETING.md#چک‌لیست-پذیرش-هر-صفحهٔ-عمومی)، اعتبارسنجی JSON-LD و فیدها، ثبت در Google Search Console؛ دسترس‌پذیری WCAG AA؛ چک‌لیست OWASP Top 10 و تست نفوذ پایه (OWASP ZAP).

## فاز ۱۲ — پایگاه‌های دادهٔ دوم، مستندات و انتشار ⬜

- Migrationهای **SQL Server** و **MySQL** و اجرای تست‌های یکپارچه‌سازی روی هر سه.
- `docs/user-guide`، `docs/admin-guide`، `docs/sysadmin-guide` (نصب لینوکس/ویندوز، تنظیمات، پشتیبان‌گیری PostgreSQL، به‌روزرسانی، مانیتورینگ) به فارسی و انگلیسی.
- **پشتیبان‌گیری و به‌روزرسانی هر نصب:** `pg_dump` زمان‌بندی‌شده + پشتیبان فایل‌های رسانه، تمرین بازیابی؛ پیش از هر به‌روزرسانی پشتیبان خودکار و سپس Migration؛ اسکریپت به‌روزرسانی برای همهٔ نصب‌ها.
- راهنمای ایمیل (SPF/DKIM) و راهنمای قانونی برای فروشنده: انطباق مالیاتی (مودیان، VAT، e-HDM) بر عهدهٔ فروشنده است.
- انتشار نسخهٔ ۱.۰.

## Backlog (خارج از نسخهٔ ۱)

فروش حضوری (POS)، محصولات دیجیتال و Paddle، فروش عمده (B2B)، اتصال به سامانهٔ مودیان / e-HDM / VAT اتحادیهٔ اروپا،
اتصال API شرکت‌های حمل، امتیاز وفاداری و کارت هدیه، ایمیل سبد رهاشده، چت آنلاین، ترجمهٔ ماشینی، پلتفرم SaaS چندفروشگاهی.
